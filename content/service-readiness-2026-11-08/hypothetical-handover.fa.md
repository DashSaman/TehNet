# قالب فرضی گزارش پشتیبانی / تحویل
این فایل قالب آموزشی است؛ پروژه، مشتری، رخداد یا نتیجهٔ واقعی نیست. قرارداد یا SLA مصوب نیست؛ همهٔ فیلدهای عملیاتی بیرون Git و در تیکت موجود تکمیل شوند.

| فیلد | نمونهٔ فرضی / روش تکمیل |
|---|---|
| شناسه و دامنه | شناسهٔ تیکت موجود؛ نام و اطلاعات مشتری در نسخه عمومی حذف |
| شرح اثر | مثلاً اختلال دسترسی یک گروه کاربر؛ تعداد/زمان فقط پس از مشاهده |
| زمان ثبت / پاسخ اولیه | دو زمان مستقل؛ پاسخ به معنی رفع نیست |
| زمان شروع بررسی / رفع / تأیید | هرکدام مستقل و نامعلوم تا ثبت شاهد؛ توقف انتظار دسترسی/قطعه/تأمین‌کننده جدا ثبت شود |
| فرضیه / شاهد | مشاهده از استنتاج جدا؛ خروجی خام و کانفیگ در فایل عمومی قرار نگیرد |
| اقدام مصوب | هدف، مسئول، پنجره، دسترسی جایگزین و راه برگشت مورد توافق |
| آزمون پذیرش | سناریو، روش، قبل/بعد همسان، نتیجه و محدودیت؛ اگر اجرا نشده NOT_TESTED |
| باقی‌مانده / مسئول | وابستگی، اثر حل‌نشده و موعد مورد توافق؛ بدون زمان تضمینی ساختگی |
| تحویل / پیگیری | تأیید نماینده مجاز، ارجاع به تیکت canonical و دامنه پشتیبانی بعدی |
| دسترسی موقت | بسته‌شدن نشست و وضعیت دسترسی طبق مجوز و وابستگی بررسی شود؛ ادعای حذف همه credentialها نشود |

## معرفی روش کار پیشنهادی
نام مسئول و تخصص تأییدشده، نقش در همین دامنه و روش آزمون/مستندسازی مشخص شود. تا معرفی متخصص و شواهد قابل انتشار احراز نشده، نام، گواهی یا سابقه ساخته نشود. دربارهٔ روش کار به /technical-methodology/ و برای درخواست به /services/#service-request ارجاع دهید.
