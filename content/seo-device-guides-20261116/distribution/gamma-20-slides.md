## اسلاید ۱: مسئلهٔ مشتری
**عنوان:** شبکهٔ شرکت، سرمایه است نه هزینه
**محتوا:**
- downtime یعنی توقف کسب‌وکار
- تجهیز اشتباه = هزینهٔ دوباره
- بدون نیازسنجی، انتخاب درست شانسی است
**پیشنهاد تصویر:** نمودار هزینهٔ downtime در برابر هزینهٔ نیازسنجی
**speaker notes:** با یک مثال مفهومی شروع کنید: «اگر شبکهٔ فروشگاه یک ساعت قطع شود، فروش آن ساعت از دست می‌رود.»
**منبع:** تجربهٔ صنعتی رایج؛ بدون عدد ساختگی

## اسلاید ۲: ورودی‌های نیازسنجی
**عنوان:** قبل از خرید، این‌ها را بنویسید
**محتوا:**
- تعداد کاربران و دستگاه‌ها (حالا و آیندهٔ نزدیک)
- نقشهٔ فضا و تعداد پریز شبکه
- VLANهای موردنیاز (فروش، مالی، دوربین، مهمان)
- الزامات خاص (دوربین PoE، سرور، NAS)
- بودجهٔ واقعی (نه فقط قیمت تجهیز)
**پیشنهاد تصویر:** چک‌لیست نیازسنجی (جدول)
**speaker notes:** روی اهمیت نوشتن الزامات قبل از خرید تأکید کنید.
**منبع:** تجربهٔ صنعتی رایج

## اسلاید ۳: روتر در برابر سوئیچ
**عنوان:** روتر و سوئیچ دو نقش متفاوت دارند
**محتوا:**
- روتر: مسیریابی بین شبکه‌ها (L3)، فایروال، VPN، NAT
- سوئیچ: ارتباط دستگاه‌ها در یک شبکه (L2)، PoE، VLAN
- روترسوئیچ: ترکیبی — اما CPU کوچک برای routing سنگین کافی نیست
**پیشنهاد تصویر:** diagram ساده: internet → router → switch → devices
**speaker notes:** مثال: «روتر مودم خانه، سوئیچ اتاق سرور»
**منبع:** help.mikrotik.com; صفحات رسمی MikroTik

## اسلاید ۴: پورت در برابر ظرفیت پردازش
**عنوان:** تعداد پورت ≠ قدرت پردازش
**محتوا:**
- پورت Gigabit یعنی سرعت لینک، نه ظرفیت فایروال
- rules و queues روی CPU پردازش می‌شوند
- تعداد کاربر → انتخاب CPU و RAM، نه تعداد پورت
- قبل از خرید: تعداد rules، VPN tunnelها و queueها را بنویسید
**پیشنهاد تصویر:** جدول: مدل/RAM/CPU/قابلیت
**speaker notes:** مثال: «hEX با ۵ پورت برای ۵ نفر خوب است؛ برای ۵۰ نفر با قوانین سنگین نه.»
**منبع:** صفحات رسمی MikroTik hEX/RB5009

## اسلاید ۵: نسل‌های hEX
**عنوان:** hEX قدیمی یا جدید؟
**محتوا:**
- hEX lite (RB750r2): 64MB، تک‌هسته — فقط اینترنت ساده
- hEX (RB750Gr3): 256MB، دو-هسته — دفتر کوچک استاندارد
- hEX refresh (E50UG): EN7562CT 950MHz ARM32، 512MB — نسل جدید
- hEX S (RB760iGS): +SFP فیبر +PoE-out
**پیشنهاد تصویر:** جدول مقایسهٔ ۴ مدل (RAM/CPU/پورت/قیمت MSRP)
**speaker notes:** تأکید: «قدیمی» به معنای پایان پشتیبانی نیست؛ فقط نسل سخت‌افزار قدیمی‌تر است.
**منبع:** mikrotik.com/product/hex_2024?sku=E50UG (2026-11-16)

## اسلاید ۶: RB4011 / RB5009
**عنوان:** RB4011 یا RB5009؟
**محتوا:**
- RB4011: 10x Gigabit، AL21400 چهار-هسته، 1GB، SFP+ 10G — رک‌مونت کلاسیک
- RB5009: 7x Gb + 1x 2.5G + 1x SFP+، AL32400 چهار-هسته 1.4GHz، 1GB DDR4 — جدیدتر
- RB4011: پورت بیشتر، رک‌مونت؛ RB5009: 2.5G/10G و عملکرد بهتر در RouterOS v7
**پیشنهاد تصویر:** دو ستون مقایسه (RB4011 در برابر RB5009)
**speaker notes:** «اگر ۱۰ پورت مسی لازم دارید RB4011؛ اگر 2.5G/10G آینده‌نگری RB5009.»
**منبع:** mikrotik.com/product/rb4011igs_rm; mikrotik.com/product/rb5009ugs_in

## اسلاید ۷: زمان نیاز به CCR
**عنوان:** CCR برای چه زمانی؟
**محتوا:**
- ترافیک چند-گیگابیت (۱۰G+)
- تعداد rules و VPN tunnelهای زیاد
- کور سازمانی با چند روتر
- برای دفتر معمولی بیش‌ازحد است
**پیشنهاد تصویر:** diagram: CCR2116 در مرکز با چند CRS متصل
**speaker notes:** مثال: «CCR2116 با ۱۶-هستهٔ ARM64 برای ISP و سازمان بزرگ طراحی شده.»
**منبع:** mikrotik.com/product/ccr2116_12g_4splus (2026-11-16)

## اسلاید ۸: CSS یا CRS؟
**عنوان:** CSS ساده و ارزان؛ CRS کامل و گران‌تر
**محتوا:**
- CSS: SwOS Lite فقط — L2 سوئیچینگ پایه، بدون RouterOS
- CRS: RouterOS کامل (و dual-boot با SwOS) — VLAN پیشرفته، L3HW سندشده
- CSS ارزان‌تر؛ CRS قابلیت‌های بیشتر
- CSS610: 8x GbE + 2x SFP+ 10G، $119 پیشنهادی — access ارزان
- CRS326-24G-2S+RM: 24x GbE + 2x SFP+، $209 پیشنهادی — distribution
**پیشنهاد تصویر:** diagram CSS در برابر CRS (port count + OS)
**speaker notes:** مثال: «CSS برای اتصال ساده؛ CRS وقتی VLAN و routing لازم است.»
**منبع:** mikrotik.com/product/css610_8g_2s_in; crs326_24g_2s_rm

## اسلاید ۹: محدودیت L3HW
**عنوان:** L3 hardware offloading — مرزهای سندشده
**محتوا:**
- L3HW فقط روی چیپ‌های خاص MikroTik (CRS3xx با RouterOS v7)
- فقط routeهای ساده hardware می‌شوند
- firewall rules سنگین → به CPU برمی‌گردند → سرعت می‌افتد
- هر مدل و نسخهٔ RouterOS محدودیت متفاوت دارد
**پیشنهاد تصویر:** diagram: L3HW flow (switch chip مسیر بدون CPU)
**speaker notes:** تأکید: «L3HW قابلیت رایگان نیست؛ سند رسمی را بخوانید.»
**منبع:** help.mikrotik.com L3 Hardware Offloading

## اسلاید ۱۰: PoE-in/out و بودجه
**عنوان:** PoE — استاندارد، بودجه و PSU
**محتوا:**
- PoE-out انواع: پسیو MikroTik، 802.3af (~15W)، 802.3at (~30W)
- بودجهٔ کل: جمع مصرف همهٔ دستگاه‌ها + ۲۰٪ رزرو
- PSU پیوست ممکن است برای بار کامل کافی نباشد
- netPower 16P: 16x PoE-out، max ~316W، PSU پیوست نمی‌آید
**پیشنهاد تصویر:** جدول بودجهٔ PoE (دستگاه/W/جمع)
**speaker notes:** مثال محاسبه: «۱۲ دوربین × ۱۲W + ۴ تلفن × ۶W = ۱۶۸W → PSU حداقل ۲۰۰W»
**منبع:** mikrotik.com/product/netpower_16p (صفحهٔ رسمی: PSU پیوست نمی‌آید)

## اسلاید ۱۱: SFP/SFP+
**عنوان:** ماژول نوری — SFP و SFP+ فرق دارند
**محتوا:**
- SFP: تا 1.25Gbps
- SFP+: تا 10Gbps (و در برخی مدل‌ها 25G SFP28)
- قفسه مشابه ولی سرعت و ماژول متفاوت
- سازگاری ماژول را از استاندارد چک کنید نه از شکل
**پیشنهاد تصویر:** عکس/نمودار SFP در برابر SFP+
**speaker notes:** «SFP+ در پورت SFP جا می‌رود ولی با سرعت SFP کار می‌کند.»
**منبع:** صفحات رسمی MikroTik CRS310/CRS326

## اسلاید ۱۲: VLAN برای شرکت
**عنوان:** VLAN — بخش‌بندی منطقی شبکه
**محتوا:**
- VLANها ترافیک را جدا می‌کنند (فروش، مالی، دوربین، مهمان)
- access port: یک VLAN فقط؛ trunk port: چند VLAN
- امنیت: deviceهای مهمان به VLAN جدا وインターネت فقط
**پیشنهاد تصویر:** diagram VLAN با سه بخش رنگی
**speaker notes:** مثال: «VLAN 10: کاربران؛ VLAN 20: دوربین؛ VLAN 30: مهمان — و فایروال بین‌شان.»
**منبع:** help.mikrotik.com VLAN documentation

## اسلاید ۱۳: مثال دفتر کوچک
**عنوان:** دفتر کوچک — چیدمان ساده
**محتوا:**
- hEX (RB750Gr3) به‌عنوان روتر
- CSS610-8G-2S+IN به‌عنوان سوئیچ access
- بدون VLAN پیچیده؛ فایروال روی hEX
- کل هزینهٔ تجهیز: مقرون‌به‌صرفه
**پیشنهاد تصویر:** diagram ساده: internet → hEX → CSS610 → devices
**speaker notes:** «برای دفتر تا ۱۰ نفر، این چیدمان کافی و اقتصادی است.»
**منبع:** صفحات رسمی mikrotik.com hEX و CSS610

## اسلاید ۱۴: مثال شعبه/VPN
**عنوان:** شعبه با VPN به دفتر مرکزی
**محتوا:**
- روتر شعبه: RB5009 (IPsec hardware ~1.4Gbps)
- روتر مرکزی: RB5009 یا CCR2004
- سوئیچ access: CSS610
- VPN tunnel: IPsec یا WireGuard بسته به نیاز
**پیشنهاد تصویر:** diagram: شعبه ↔ VPN tunnel ↔ دفتر مرکزی
**speaker notes:** «IPsec برای امنیت استاندارد؛ WireGuard برای سادگی و سرعت.»
**منبع:** صفحات رسمی RB5009 (IPsec ~1.4Gbps)

## اسلاید ۱۵: مثال دوربین/تلفن PoE
**عنوان:** دوربین و تلفن PoE — netPower 16P
**محتوا:**
- netPower 16P: 16x GbE PoE-out
- دوربین: ~۱۲W هرکدام
- تلفن: ~۶W هرکدام
- بودجهٔ کل + ۲۰٪ رزرو → PSU مناسب انتخاب کنید
**پیشنهاد تصویر:** diagram: netPower 16P → cameras + phones
**speaker notes:** «PSU پیوست نمی‌آید — PSU جدا با ظرفیت مناسب لازم است.»
**منبع:** mikrotik.com/product/netpower_16p (2026-11-16)

## اسلاید ۱۶: مثال NAS/10G
**عنوان:** سرور و NAS با 10G
**محتوا:**
- CRS309-1G-8S+IN: 8x SFP+ 10G
- سرورها و NAS با NICهای SFP+ متصل
- routing بین VLANها به روتر اصلی
- بدون PoE — مخصوص data
**پیشنهاد تصویر:** diagram: CRS309 → servers + NAS
**speaker notes:** «CRS309 ارزان‌ترین سوئیچ 10G MikroTik برای attachment مستقیم است.»
**منبع:** mikrotik.com/product/crs309_1g_8s_in

## اسلاید ۱۷: ارتقای تجهیزات قدیمی
**عنوان:** چه زمانی ارتقا بدهم؟
**محتوا:**
- RAM پر → قوانین جدید جا نمی‌شوند
- CPU ضعیف → ترافیک سنگین افت می‌کند
- نسل جدید RouterOS v7 → سخت‌افزار جدید بهینه‌تر
- مسیر ارتقا: hEX lite → hEX → RB5009 (یا CCR برای سازمانی)
**پیشنهاد تصویر:** مسیر ارتقا (نمودار پله‌ای)
**speaker notes:** «ارتقا وقتی ارزش دارد که نیاز واقعی جدید داشته باشید، نه فقط برای مدل جدیدتر.»
**منبع:** صفحات رسمی MikroTik

## اسلاید ۱۸: چک‌لیست خرید
**عنوان:** قبل از خرید، این‌ها را چک کنید
**محتوا:**
- SKU دقیق و revision
- RAM و CPU برای بار پیش‌بینی‌شده
- تعداد و نوع پورت‌ها (GbE/2.5G/SFP/SFP+)
- PoE-out استاندارد و بودجهٔ توان
- RouterOS نسخه و license level
- PSU پیوست یا جدا
**پیشنهاد تصویر:** چک‌لیست (جدول ۷ سطری)
**speaker notes:** «هر مورد را با سند رسمی MikroTik تطبیق دهید.»
**منبع:** صفحات رسمی mikrotik.com

## اسلاید ۱۹: تحویل و پشتیبانی
**عنوان:** اجرا بدون تحویل مستند = نصف کار
**محتوا:**
- پیکربندی مستندشده (فایل backup + export)
- گزارش تغییرات (قبل/بعد)
- چک‌لیست پذیرش (تست ارتباط، VLAN، PoE)
- مسیر پشتیبانی (رخداد، نگهداری دوره‌ای)
**پیشنهاد تصویر:** چک‌لیست تحویل
**speaker notes:** «تحویل بدون مستندات، وابستگی به حافظهٔ فرد اجراکننده می‌سازد.»
**منبع:** تجربهٔ صنعتی رایج

## اسلاید ۲۰: جمع‌بندی و مسیر اقدام
**عنوان:** قدم بعدی شما
**محتوا:**
- نیازسنجی را بنویسید (کاربران، VLANها، PoE، سرعت)
- تجهیز مناسب را از راهنماهای MikroTik انتخاب کنید
- برای نیازسنجی و اجرا با متخصص تماس بگیرید
- TehNet: نیازسنجی، کانفیگ، پشتیبانی و مستندسازی
**پیشنهاد تصویر:** لوگوی TehNet + اطلاعات تماس
**speaker notes:** «قبل از خرید، نیازسنجی کوتاه جلوی هزینهٔ دوباره را می‌گیرد.»
