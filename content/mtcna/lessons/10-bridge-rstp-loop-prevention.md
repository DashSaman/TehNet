> پیش‌نویس مستقل آموزشی تهنت، کوتاه‌شدهٔ تهران نتورک؛ اجرای آزمایشگاه و تهیهٔ تصاویر هنوز انجام نشده است. مبنای برنامه‌ریزی RouterOS 7.25.1 و WinBox 4.5 است؛ نمایش نسخهٔ 7.26 در مستندات جدید، تأیید اجرای این تمرین روی آن نسخه نیست. همهٔ نتیجه‌ها «مورد انتظار» هستند. این متن ادعای تطبیق با ویدئوی منتشرشده یا آزمون رسمی جدید ندارد.

## پاسخ سریع

Bridge چند پورت اترنت را در یک شبکهٔ لایهٔ دو قرار می‌دهد. برای این آزمایش، ether2 و ether4 عضو bridge-lan می‌شوند و IP مدیریت LAN روی خود بریج قرار می‌گیرد. RSTP به بریج‌های سازگار کمک می‌کند مسیرهای افزونه را بدون حلقه نگه دارند؛ فعال بودن آن جای بررسی کابل‌کشی و مرز شبکه را نمی‌گیرد. ether1 که برای WAN و ether3 که برای اتصال دو روتر رزرو شده‌اند، عضو این بریج نیستند.

## هدف‌ها و پیش‌نیاز

پس از تمرین باید تفاوت «رابط بریج» و «پورت عضو» را توضیح دهید، MACهای یادگرفته‌شده را پیدا کنید و دلیل خطرناک بودن اتصال دو سر کابل به یک شبکهٔ بی‌حفاظ را بفهمید. دانستن آدرس‌دهی درس قبل لازم است. دستگاه باید حداقل چهار رابط یا معادل مجازی آن داشته باشد؛ اگر ندارد، این نگاشت را بدون طراحی جایگزین اجرا نکنید. دسترسی کنسول محلی و یادداشت وضعیت اولیه برای انتقال IP لازم است.

## آماده‌سازی ماشین مجازی برای چهار رابط

R1 در درس اول دو کارت داشت. پیش از این درس آن را خاموش کنید، دو کارت مجازی تازه اضافه کنید و MAC کارت‌های اولیه را حفظ و دوباره تطبیق دهید. ether3 را برای شبکهٔ جداگانهٔ LAB-TRANSIT و اتصال روتر دوم در درس ۱۲ رزرو کنید. ether4 و میزبان B را به سگمنت مجازی جدا با نام LAB-LAN-B وصل کنید؛ ether2 و میزبان A در LAB-LAN اولیه می‌مانند. در این تمرین ether2 و ether4 را به یک سوئیچ مجازی مشترک متصل نکنید، چون مسیر اضافی می‌تواند حلقه یا یادگیری MAC روی پورت نامنتظره ایجاد کند. پس از روشن‌کردن، نگاشت هر چهار رابط را با MACها تأیید کنید.

## آدرس‌بندی و طرح اتصال

R1 روی ether2 آدرس 10.77.10.1/24 دارد. میزبان A با 10.77.10.10/24 به ether2 و میزبان B با 10.77.10.11/24 به ether4 متصل می‌شود؛ هر دو گیت‌وی 10.77.10.1 دارند. هیچ اتصال دیگری بین دو میزبان و سوئیچ‌های پیرامون نباشد. ether4 باید واقعاً آزاد و فاقد IP، DHCP client و عضویت قبلی باشد. اگر DHCP Server درس قبلی روی ether2 فعال است، در این سناریوی استاتیک فقط همان سرور شناسایی‌شده را پیش از کار غیرفعال کنید و نام و وضعیتش را یادداشت کنید. هیچ DHCPای به LAN واقعی وصل نشود.

## مراحل اجرا

۱. **وضعیت را پیش از تغییر بخوانید.** در WinBox، Interfaces، IP > Addresses و Bridge > Ports را کنار هم بررسی کنید. هر پورتی که از قبل عضو بریج است نیازمند بازبینی طرح است؛ افزودن دوباره یا حذف عضویت موجود بخشی از دستور خودکار نیست. از کنسول یا Safe Mode در نشست محلی استفاده کنید؛ انتقال IP ممکن است اتصال IP مدیریت را موقتاً قطع کند.

```routeros
/interface bridge print detail
/interface bridge port print detail
/ip address print detail where address="10.77.10.1/24"
/ip dhcp-server print detail
/interface print detail where name=ether4
```

۲. **بریج را بسازید و حالت پروتکل را صریح بنویسید.** در Bridge > Bridges گزینهٔ افزودن را بزنید، Name را bridge-lan و Protocol Mode را rstp انتخاب کنید. پیش از اجرا مطمئن شوید بریجی با همین نام وجود ندارد. این فرمان برای ایجاد اولیه است و اسکریپت تکرارپذیر نصب عمومی نیست.

```routeros
/interface bridge add name=bridge-lan protocol-mode=rstp comment="TEHNET-L10-bridge"
/interface bridge port add bridge=bridge-lan interface=ether2 comment="TEHNET-L10-ether2"
/interface bridge port add bridge=bridge-lan interface=ether4 comment="TEHNET-L10-ether4"
```

در Bridge > Ports دقیقاً همین دو ردیف را ببینید. LAN را با افزودن WAN گسترش ندهید؛ عضویت ether1 ممکن است مرز بین شبکهٔ بالادست و کلاینت را از بین ببرد. یک Bridge ذاتاً قانون NAT یا سیاست امنیتی جدید ایجاد نمی‌کند و اشتباه در اعضا را فایروال به‌صورت خودکار اصلاح نمی‌کند.

۳. **آدرس لایهٔ سه را منتقل کنید.** ابتدا بررسی کنید جست‌وجوی زیر دقیقاً یک آدرس روی ether2 برمی‌گرداند. سپس همان مورد را به bridge-lan انتقال دهید. آدرس جدید هم‌نام اضافه نکنید، زیرا دو نسخه از یک آدرس، خواندن وضعیت و بازگشت را دشوار می‌کند. در IP > Addresses، همان ردیف را باز کنید و Interface را تغییر دهید.

```routeros
/ip address print detail where address="10.77.10.1/24" and interface=ether2
/ip address set [find where address="10.77.10.1/24" and interface=ether2] interface=bridge-lan
```

نتیجهٔ مورد انتظار این است که ردیف آدرس فقط یک بار وجود داشته باشد و رابطش bridge-lan باشد. از هر میزبان گیت‌وی را ping کنید. اگر DHCP را در شروع غیرفعال کرده‌اید، همچنان از IP استاتیک استفاده کنید؛ انتقال DHCP به بریج یک تغییر مستقل است و باید شبکه، pool و رابط آن جداگانه بررسی شود.

۴. **یادگیری MAC را مشاهده کنید.** بین A و B ترافیک کوتاه ایجاد کنید. در Bridge > Hosts، MAC هر میزبان و پورت ورودی آن را پیدا کنید. ARP روتر و جدول Hosts بریج نقش یکسان ندارند: اولی نگاشت IP همسایه، دومی یادگیری نشانی‌های لایهٔ دو را نشان می‌دهد. ارتباط A به B در همان subnet معمولاً نیازمند عبور مسیریابی از IP روتر نیست.

```routeros
/interface bridge host print where bridge=bridge-lan
/interface bridge monitor [find where name=bridge-lan] once
/interface bridge port print detail where bridge=bridge-lan
```

۵. **RSTP را بدون ایجاد طوفان بررسی کنید.** در توپولوژی فعلی فقط یک مسیر بین هر میزبان و بریج وجود دارد. انتظار پورت مسدودشده صرفاً به‌دلیل روشن بودن RSTP درست نیست. نقش root و حالت پورت‌ها را ثبت کنید، اما عمداً حلقه نسازید. تمرین افزونگی به دو بریج آزمایشی جداشده و طراحی کنترل‌شده نیاز دارد و در این درس اجرا نمی‌شود. قرار دادن کورکورانهٔ همهٔ پورت‌ها در حالت edge می‌تواند برداشت اشتباه از اتصال سوئیچ به سوئیچ ایجاد کند.

## جدول عیب‌یابی

| نشانه | بررسی محدود | دلیل احتمالی |
|---|---|---|
| A به روتر می‌رسد ولی B نمی‌رسد | ether4 و کارت مجازی B | عضویت یا اتصال اشتباه |
| IP مدیریت پس از انتقال قطع شد | کنسول و ردیف آدرس | IP روی پورت عضو باقی مانده یا فیلتر وابسته به رابط است |
| MAC یک میزبان روی پورت‌های مختلف جابه‌جا می‌شود | کابل‌ها و اتصال‌های اضافی | مسیر تکراری یا حلقهٔ احتمالی |
| هیچ پورت blocking نیست | طرح تک‌مسیره را بخوانید | این وضعیت می‌تواند کاملاً طبیعی باشد |

## تمرین و معیار پذیرش

طرح را روی کاغذ بکشید و کنار هر رابط کاربردش را بنویسید. معیار موفقیت، پاسخ گیت‌وی از دو میزبان، دیده شدن MACها روی پورت درست و نبود عضویت ether1 و ether3 است. توضیح دهید چرا حذف IP بریج ارتباط لایهٔ دوی A و B را الزاماً قطع نمی‌کند، اما مدیریت IP و گیت‌وی را مختل می‌کند. این استدلال باید با مرز لایهٔ دو و سه سازگار باشد.

## بازگشت محدود

بازگشت را از کنسول انجام دهید. ابتدا IP را به ether2 برگردانید، سپس فقط پورت‌های همین درس و خود بریج ساخته‌شده را حذف کنید. اگر چیز دیگری از بریج استفاده می‌کند، پیش از حذف آن وابستگی را حل کنید. DHCP قبلی را فقط پس از بازگشت به رابط و توپولوژی اولیه به وضعیت یادداشت‌شده برگردانید.

```routeros
/ip address set [find where address="10.77.10.1/24" and interface=bridge-lan] interface=ether2
/interface bridge port remove [find where comment="TEHNET-L10-ether4"]
/interface bridge port remove [find where comment="TEHNET-L10-ether2"]
/interface bridge remove [find where name=bridge-lan and comment="TEHNET-L10-bridge"]
```
