> پیش‌نویس مستقل تهنت؛ اجرای لابراتوار و ثبت تصویر هنوز انجام نشده است. خروجی‌های این متن «مورد انتظار» هستند، نه نتیجهٔ آزمون واقعی.

## پاسخ سریع و نتیجهٔ این قسمت

Backup فایل باینری برای بازیابی پیکربندی همان روتر است؛ Export متن فرمان‌ها برای خواندن، مقایسه و انتقال انتخابی تنظیمات است. این دو مکمل یکدیگرند. فایل Backup را با رمز بسازید، هر دو فایل را خارج از روتر نگه دارید و پیش از Restore بدانید ارتباط قطع و روتر راه‌اندازی مجدد خواهد شد. داشتن فایل به‌تنهایی ثابت نمی‌کند مسیر بازیابی آزموده شده است.

پایان این قسمت باید بتوانید توضیح دهید کدام فایل برای بازگرداندن R1 مناسب‌تر است و چرا یک Export معمولی جای همهٔ داده‌ها و رمزهای دستگاه را نمی‌گیرد. تمرین واقعی Restore فقط روی همین ماشین آزمایشگاهی، با Snapshot و کنسول آماده انجام می‌شود. وضعیت این مقاله همچنان پیش‌نویس و آزموده‌نشده است؛ مراحل زیر برنامهٔ اجرای شما هستند، نه گزارش Restore موفق نویسنده.

## پیش‌نیاز و تصمیم پیش از شروع

R1 در LAB-LAN آدرس 10.77.10.1 دارد و حساب مدیریتی قابل استفاده از قسمت چهارم آماده است. فضای ذخیرهٔ فایل روی روتر و رایانهٔ مدیریت را بررسی کنید. رمز Backup را در جایی امن و جدا از فایل نگه دارید. نام فایل، تاریخ، نسخهٔ RouterOS، دستگاه مبدأ و دلیل تهیه را ثبت کنید؛ نامی مثل `backup-final-new2` برای تشخیص نسخهٔ مناسب در زمان بحران کافی نیست.

پیش از تمرین اختیاری Restore، وضعیت ماشین را Snapshot بگیرید و مطمئن شوید کنسول VM حتی بدون شبکه باز می‌شود. این Snapshot فقط برای همین لابراتوار است و جای پشتیبان خارج دستگاه را نمی‌گیرد. اگر به کنسول یا حساب لازم دسترسی ندارید، قسمت ساخت و دریافت فایل را انجام دهید و Restore را اجرا نکنید.

## چه چیزی در هر فایل داریم؟

| قالب | کاربرد آموزشی | محدودیت کلیدی |
|---|---|---|
| `.backup` | بازگرداندن پیکربندی همان R1 | اطلاعات حساس دارد؛ برای همان دستگاه و ترجیحاً همان نسخه |
| `.rsc` | خواندن و مقایسهٔ تنظیمات متنی | رمز کاربران و همهٔ اقلام لازم را شامل نمی‌شود |
| Snapshot VM | برگشت محیط آزمایشگاهی | وابسته به زیرساخت مجازی؛ پشتیبان قابل انتقال RouterOS نیست |

[مستند Backup](https://manual.mikrotik.com/docs/getting-started/configuration-management/backup/) تأکید می‌کند بازیابی روی همان دستگاه قابل اتکاتر است و اطلاعات MAC نیز در فایل وجود دارد. بنابراین فایل باینری R1 را روی R2 بارگذاری نکنید تا «تنظیماتش شبیه شود». برای انتقال بین دستگاه‌ها، Export را بررسی و متناسب‌سازی می‌کنیم و نام اینترفیس، قابلیت سخت‌افزاری و تفاوت نسخه را جداگانه می‌سنجیم.

## گام اول: ثبت وضعیت و ساخت Backup

ابتدا نام و نسخه را ثبت و فهرست فایل‌ها را ببینید:

```routeros
/system identity print
/system resource print
/file print
```

در WinBox وارد Files شوید و گزینهٔ Backup را انتخاب کنید. نامی مثل `r1-before-l05` و رمز قوی شخصی وارد کنید. اگر نسخهٔ رابط شما گزینهٔ جلوگیری از رمزگذاری دارد، آن را برای این تمرین فعال نکنید. استفاده از رمز به معنی مجاز شدن انتشار فایل نیست؛ این فایل همچنان یک دارایی حساس است.

معادل CLI زیر الگو است؛ عبارت رمز باید قبل از اجرا جایگزین شود. هنگام ضبط صفحه روش گرافیکی یا توقف ضبط برای ورود رمز مناسب‌تر است:

```routeros
/system backup save name=r1-before-l05 password="REPLACE-WITH-PRIVATE-BACKUP-PASSWORD"
/file print where name~"r1-before-l05"
```

خروجی مورد انتظار، وجود `r1-before-l05.backup` با اندازهٔ غیرصفر است. این بررسی فقط ایجاد فایل را نشان می‌دهد، نه امکان Restore قطعی. از WinBox فایل را به پوشهٔ امن رایانهٔ مدیریت دانلود کنید. پس از دریافت، نام و اندازهٔ فایل را کنترل کنید و مسیر را در دفترچه بنویسید. نسخهٔ یگانهٔ فایل را روی همان روتر باقی نگذارید؛ خرابی دیسک می‌تواند فایل و تنظیمات را با هم از بین ببرد.

## گام دوم: ساخت Export قابل خواندن

برای Export معمولی از ریشهٔ منو اجرا کنید:

```routeros
/export file=r1-before-l05
/file print where name~"r1-before-l05"
```

خروجی مورد انتظار، فایل `r1-before-l05.rsc` در کنار Backup است. آن را نیز دانلود و با ویرایشگر متن باز کنید. دنبال آدرس 10.77.10.1/24 و نام کاربر تمرینی بگردید؛ انتظار نداشته باشید رمز همان کاربر را ببینید. Export معمولی بر تغییرات پیکربندی تمرکز دارد و لزوماً همهٔ مقادیر پیش‌فرض را نمی‌نویسد. منبع این رفتار [Configuration Management](https://manual.mikrotik.com/docs/getting-started/configuration-management/) است.

برای دیدن محدودهٔ کوچک‌تر، `/ip address export` را در ترمینال اجرا کنید. این دستور نمایش متنی همان بخش را می‌دهد و آدرس جدید نمی‌سازد. Export محدود برای بررسی تفاوت‌ها خواناتر است. Import برعکس، فرمان‌ها را اجرا می‌کند؛ فایل ناشناخته را صرفاً چون پسوند rsc دارد وارد نکنید. ابتدا خط‌ها را بخوانید و آثار add، set و remove را تشخیص دهید.

پارامتر نمایش اطلاعات حساس را برای این درس فعال نکنید. پنهان بودن رمزهای حساس در خروجی معمولی تضمین نمی‌کند متن برای انتشار عمومی مناسب است؛ نام کاربر، آدرس‌ها، توضیح‌ها و ساختار شبکه هم اطلاعات دارند. [فهرست منوهای دارای پارامتر حساس](https://manual.mikrotik.com/docs/getting-started/configuration-management/list-of-menus-with-sensitive-parameters/) کمک می‌کند تفاوت دادهٔ پنهان و دادهٔ قابل مشاهده را بشناسید.

## گام سوم: تمرین اختیاری Restore با شرط روشن

این تمرین فقط روی R1 جدا و با امکان بازگردانی Snapshot اجرا می‌شود. نخست تأیید کنید Backup متعلق به همین ماشین و نسخهٔ RouterOS فعلی است و رمز آن را دارید. یک تغییر کم‌خطر مثل تغییر Identity از نام فعلی به `R1-RESTORE-CHECK` انجام دهید. پس از Restore باید نام ذخیره‌شده در زمان Backup برگردد؛ این یک معیار مشخص برای تشخیص نتیجه است.

در Files، Backup درست را انتخاب و Restore را باز کنید. نام فایل و دستگاه را دوباره بخوانید، رمز را وارد کنید و تنها پس از آماده بودن کنسول، راه‌اندازی مجدد را تأیید کنید. معادل CLI برای فایل همین تمرین `/system backup load name=r1-before-l05` است؛ ورود رمز و تأیید را طبق پیام واقعی انجام دهید. دستور را داخل اسکریپت یا Paste طولانی نگذارید. Safe Mode از Restore نیازمند Reboot حفاظت نمی‌کند.

بعد از بالا آمدن، از کنسول وضعیت را ببینید و سپس WinBox را دوباره وصل کنید. نام روتر، IP LAN، حساب مورد انتظار و وضعیت سرویس‌های مدیریت را با یادداشت پیش از Backup مقایسه کنید. برگشت فقط یک مقدار کافی نیست؛ ممکن است برای ورود مجدد به رمز حسابی نیاز داشته باشید که در زمان Backup موجود بوده است.

## عیب‌یابی و بازگشت

| نشانه | بررسی هدفمند |
|---|---|
| فایل ساخته نمی‌شود | فضای آزاد، مجوز حساب و نام فایل را بررسی کنید |
| Backup دانلود نشده است | وجود فایل در میزبان و اندازهٔ آن را تأیید کنید |
| رمز Restore پذیرفته نمی‌شود | رمز Backup را از رمز ورود روتر تفکیک کنید؛ حدس مکرر نزنید |
| پس از Restore ورود ممکن نیست | کنسول، آدرس و حساب‌های زمان تهیهٔ Backup را بررسی کنید |
| Import خطا دارد | اجرای بیشتر را متوقف کنید؛ نسخه، نام اینترفیس و دستور خطادار را بخوانید |

تمرین اجباری این درس، تولید و دریافت هر دو قالب و نوشتن محدودیت هرکدام است. تمرین Restore تنها در صورت اجرای واقعی با نتیجهٔ ثبت‌شده پذیرفته می‌شود. اگر Restore شکست خورد، از Snapshot اولیهٔ همین VM برگردید و علت را بررسی کنید؛ نصب مجدد تصادفی نسخه‌ها، حذف فایل‌ها یا Reset دسته‌جمعی راه تشخیص نیست. در پایان فایل‌های لازم را در محل امن نگه دارید و تنها نسخه‌های اضافی با نام دقیق را از Files حذف کنید، نه همهٔ محتوای روتر را.
