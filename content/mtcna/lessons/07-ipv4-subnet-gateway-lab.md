> پیش‌نویس مستقل تهنت؛ اجرای لابراتوار و ثبت تصویر هنوز انجام نشده است. خروجی‌های این متن «مورد انتظار» هستند، نه نتیجهٔ آزمون واقعی.

## پاسخ سریع و نتیجهٔ این قسمت

IP آدرس یک رابط در شبکه است؛ Prefix یا ماسک مشخص می‌کند کدام بخش آدرس، شبکه را شناسایی می‌کند؛ Gateway مسیر خروج به مقصدهای خارج آن شبکه است. برای اتصال رایانهٔ 10.77.10.10/24 به روتر 10.77.10.1/24، Gateway اینترنت لازم نیست چون هر دو در یک زیرشبکه‌اند. برای رسیدن به مقصدی خارج این زیرشبکه، رایانه معمولاً بسته را به Gateway خود می‌دهد و روتر باید مسیر مناسب بعدی را داشته باشد.

در پایان درس باید بتوانید پیش از تنظیم روتر، آدرس شبکه، محدودهٔ میزبان و Broadcast یک /24 را بنویسید و دلیل شکست یک Ping را به آدرس، اتصال یا مسیر نسبت دهید. حفظ کردن 255.255.255.0 بدون فهم محدودهٔ شبکه کافی نیست؛ دو آدرس ظاهراً شبیه ممکن است با Prefix متفاوت رفتار متفاوتی داشته باشند.

## پیش‌نیاز و توپولوژی

R1 و رایانهٔ مدیریت از قسمت دوم حاضرند. LAN روی ether2 و بدون Bridge است. به اینترفیس bridge-lan دستور ندهید؛ در این مرحله چنین اینترفیسی نداریم. ether1 فقط روی شبکهٔ بالادست ایزوله قرار می‌گیرد. وجود یک VM یا روتر آزمایشی با آدرس 10.77.0.1 اختیاری است؛ اگر آن را نساخته‌اید، سناریوی WAN و Default Route را اجرا نکنید.

| رابط یا میزبان | آدرس | نقش |
|---|---|---|
| R1 ether2 | 10.77.10.1/24 | دروازهٔ LAN |
| رایانهٔ آزمایشی | 10.77.10.10/24 | میزبان LAN |
| R1 ether1، فقط در سناریوی بالادست ثابت | 10.77.0.2/24 | رابط WAN آزمایشگاهی |
| روتر بالادست، فقط اگر واقعاً ساخته شده | 10.77.0.1/24 | همسایهٔ گام بعدی |

آدرس‌های LAN و WAN عمداً در دو زیرشبکه‌اند. اگر هر دو طرف روتر یک زیرشبکه را استفاده کنند، تشخیص مسیر و همسایه پیچیده و سناریوی این درس نقض می‌شود. این آدرس‌ها خصوصی‌اند و قرار دادن آن‌ها روی یک رابط، دسترسی اینترنت ایجاد نمی‌کند. [مبانی شبکهٔ رسمی](https://manual.mikrotik.com/docs/getting-started/networking-fundamentals/) برای مرور لایهٔ شبکه و آدرس‌دهی مناسب است.

## درک /24 با محاسبهٔ روشن

IPv4 چهار بخش هشت‌بیتی دارد. Prefix برابر ۲۴ یعنی ۲۴ بیت نخست شبکه‌اند و ۸ بیت برای بخش میزبان باقی می‌ماند. برای شبکهٔ معمولی 10.77.10.0/24، آدرس شبکه 10.77.10.0، Broadcast برابر 10.77.10.255 و محدودهٔ معمول میزبان 10.77.10.1 تا 10.77.10.254 است. آدرس شبکه و Broadcast را در این LAN به رایانه اختصاص نمی‌دهیم.

برای رایانهٔ 10.77.10.10/24، مقصد 10.77.10.1 محلی است و مقصد 10.77.0.1 خارج شبکه محسوب می‌شود. شبکهٔ دوم با وجود اشتراک دو عدد اول، شبکهٔ LAN ما نیست. اینجا رایانه برای مقصد غیرمحلی از Gateway استفاده می‌کند؛ روتر نیز بر اساس جدول مسیر تصمیم می‌گیرد بسته را به کدام رابط و گام بعدی بفرستد. Gateway یک نام قراردادی برای «اینترنت» نیست؛ باید آدرس قابل دسترس یک گام بعدی واقعی باشد.

در یک /25، مرز زیرشبکه در وسط همین فضای آخر تغییر می‌کند و دو محدودهٔ جدا شکل می‌گیرد. برای تمرین روی کاغذ، شبکهٔ آدرس 10.77.10.130/25 را پیدا کنید: محدودهٔ آن از 10.77.10.128 شروع می‌شود و Broadcast آن 10.77.10.255 است. این مثال را فعلاً روی R1 اعمال نکنید؛ تغییر ماسک مدیریت می‌تواند ارتباط را قطع کند.

## گام اول: تأیید LAN

در WinBox مسیر IP → Addresses را باز کنید. 10.77.10.1/24 باید روی ether2 باشد. در CLI:

```routeros
/ip address print detail where interface=ether2
/ip route print detail
```

اگر آدرس LAN از قسمت دوم وجود دارد، دوباره آن را اضافه نکنید. اگر به Snapshot تمیز برگشته‌اید، با کنسول و فقط پس از اطمینان از نبود آدرس، همان تنظیم قسمت دوم را بسازید. Prefix را همراه آدرس وارد کنید؛ فیلد Network معمولاً از آدرس و Prefix محاسبه می‌شود. [مرجع Address](https://manual.mikrotik.com/docs/cli-reference/ip/address/) این رابطه را توضیح می‌دهد.

روی رایانهٔ آزمایشی IP برابر 10.77.10.10/24 بگذارید. ابتدا بدون Gateway، 10.77.10.1 را Ping کنید. سپس Gateway رایانه را 10.77.10.1 قرار دهید و همان Ping را تکرار کنید. خروجی مورد انتظار، امکان دسترسی در هر دو حالت است؛ چون بستهٔ مقصد محلی اساساً برای رسیدن به روتر از Default Gateway استفاده نمی‌کند. این آزمایش روی کارت مجازی LAB-LAN انجام می‌شود، نه کارت اینترنت روزمرهٔ میزبان.

## گام دوم: WAN ثابت، تنها با بالادست موجود

اگر واقعاً یک بالادست جدا با آدرس 10.77.0.1 دارید، ابتدا روی ether1 آدرس و DHCP Client را بررسی کنید. در این سناریو نباید برای همان رابط تنظیم ثابت و دریافت خودکار متداخل ایجاد شود:

```routeros
/ip address print detail where interface=ether1
/ip dhcp-client print detail where interface=ether1
```

فقط روی ether1 فاقد تنظیم متداخل، آدرس آزمایشی را اضافه کنید:

```routeros
/ip address add address=10.77.0.2/24 interface=ether1 comment="TEHNET-L07-WAN"
/ping 10.77.0.1 count=4
```

خروجی مورد انتظار Ping فقط وقتی پاسخ است که بالادست، لینک و سیاست ICMP آن درست باشند. عدم پاسخ را فوراً با افزودن مسیر پیش‌فرض حل نکنید؛ دو آدرس در همین زیرشبکه برای ارتباط مستقیم به Default Route نیاز ندارند. اول رابط، MAC، شبکهٔ مجازی و آدرس گام بعدی را بررسی کنید.

## گام سوم: مسیر پیش‌فرض و مسیر برگشت

اضافه شدن آدرس روی یک رابط فعال معمولاً مسیر متصل همان شبکه را در جدول ایجاد می‌کند. مسیر متصل 10.77.0.0/24 با مسیر پیش‌فرض 0.0.0.0/0 فرق دارد. اولی فقط شبکهٔ خودش را پوشش می‌دهد و دومی برای مقصدهایی به کار می‌رود که مسیر دقیق‌تری ندارند. [Routing Decision](https://manual.mikrotik.com/docs/user-guides/routing-and-networking-protocols/routing-decision/) منبع رفتار مسیرهای متصل و تصمیم مسیریابی است.

فقط اگر Gateway واقعی و قابل دسترس دارید و هیچ Default Route دیگری قرار نیست استفاده شود، از IP → Routes مسیر پیش‌فرض با Gateway برابر 10.77.0.1 بسازید. معادل محدود به همین تمرین:

```routeros
/ip route print detail where dst-address=0.0.0.0/0
/ip route add dst-address=0.0.0.0/0 gateway=10.77.0.1 comment="TEHNET-L07-DEFAULT"
```

دستور دوم را فقط بعد از بررسی نتیجهٔ اول اجرا کنید. این مسیر، DNS یا NAT را پیکربندی نمی‌کند. برای رسیدن LAN به مقصدهای آن‌طرف بالادست، مسیر برگشت به 10.77.10.0/24 یا طراحی NAT لازم می‌شود که موضوع بعدی دوره است. موفق شدن Ping خود R1 به بالادست، عبور کامل ترافیک رایانهٔ LAN را ثابت نمی‌کند. [پیکربندی اولیه](https://manual.mikrotik.com/docs/getting-started/first-time-configuration/) تفاوت اتصال خود روتر و اینترنت کاربران را روشن می‌کند.

## عیب‌یابی، تمرین و بازگشت

| نشانه | بررسی اول |
|---|---|
| رایانه به روتر Ping ندارد | آدرس، ماسک و اتصال LAB-LAN را بررسی کنید |
| R1 به 10.77.0.1 نمی‌رسد | وجود واقعی بالادست و ether1 را کنترل کنید |
| Gateway اشتباه یا غیرفعال است | مطمئن شوید گام بعدی در شبکهٔ مستقیم قابل دسترس است |
| IP مقصد پاسخ می‌دهد ولی نام نه | مشکل نام‌گشایی را از مسیریابی جدا کنید |
| R1 پاسخ می‌گیرد ولی کلاینت نه | Gateway کلاینت، مسیر برگشت و سیاست عبور را بررسی کنید |

سه مقصد 10.77.10.20، 10.77.0.1 و 10.77.11.1 را برای میزبان 10.77.10.10/24 محلی یا غیرمحلی طبقه‌بندی کنید و دلیل بنویسید. معیار قبولی، تشخیص فقط مقصد اول به‌عنوان محلی و توضیح نیاز دو مقصد دیگر به مسیریابی است. برای بازگشت سناریوی WAN، فقط رکوردهای دارای Comment همین درس را حذف کنید: نخست مسیر `TEHNET-L07-DEFAULT` و سپس آدرس `TEHNET-L07-WAN`. آدرس مدیریت ether2 را نگه دارید. اگر سناریوی اختیاری را اجرا نکرده‌اید، هیچ حذف لازم نیست.
