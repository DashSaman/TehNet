> پیش‌نویس مستقل تهنت؛ اجرای لابراتوار و ثبت تصویر هنوز انجام نشده است. خروجی‌های این متن «مورد انتظار» هستند، نه نتیجهٔ آزمون واقعی.

## پاسخ سریع و نتیجهٔ این قسمت

DHCP Server به کلاینت آدرس و تنظیمات شبکه اجاره می‌دهد؛ DHCP Client از یک سرور چنین تنظیماتی می‌گیرد. R1 می‌تواند روی ether2 سرور LAN و در سناریویی مستقل روی ether1 کلاینت بالادست باشد. این دو نقش را روی یک اینترفیس و یک دامنهٔ پخش مخلوط نمی‌کنیم. پایان این درس باید یک رایانهٔ آزمایشی در LAB-LAN از بازهٔ تعیین‌شده آدرس بگیرد و بتواند 10.77.10.1 را Ping کند.

گرفتن IP مساوی داشتن اینترنت نیست. DHCP می‌تواند Gateway و DNS معرفی کند، ولی وجود آن مقادیر به معنی آماده بودن مسیریابی، NAT یا نام‌گشایی نیست. برای اینکه نتیجهٔ آزمایش قابل تفسیر بماند، ابتدا فقط تخصیص آدرس و دسترسی به دروازهٔ محلی را می‌سنجیم. در قسمت بعد، نام‌گشایی خود روتر و تفاوت آن با پاسخ‌گویی DNS به کلاینت را جداگانه بررسی می‌کنیم.

## پیش‌نیاز و طرح آدرس

R1 روی ether2 آدرس ثابت 10.77.10.1/24 دارد. LAB-LAN به هیچ شبکهٔ واقعی Bridge نشده و DHCP داخلی مجازی‌ساز روی آن خاموش است. یک کلاینت آزمایشی جدا از رایانهٔ مدیریت پیشنهاد می‌شود تا با تغییر تنظیمات آن، نشست WinBox شما قطع نشود. رایانهٔ مدیریت می‌تواند همچنان آدرس ثابت 10.77.10.10 را نگه دارد.

| مؤلفه | مقدار تمرین |
|---|---|
| رابط سرور LAN | ether2 |
| شبکهٔ DHCP | 10.77.10.0/24 |
| Gateway معرفی‌شده | 10.77.10.1 |
| محدودهٔ Pool | 10.77.10.100 تا 10.77.10.199 |
| زمان اجارهٔ آموزشی | یک ساعت |
| DNS معرفی‌شده در این درس | ارسال نمی‌شود؛ dns-none=yes و آزمون فقط با IP |

آدرس روتر و رایانهٔ مدیریت بیرون Pool هستند تا با اجاره‌های خودکار تداخل نکنند. در این تمرین dns-none=yes را صریح تنظیم می‌کنیم؛ خالی بودن dns-server به‌تنهایی کافی نیست و می‌تواند DNS خود روتر را به کلاینت معرفی کند. نام‌گشایی کلاینت معیار قبولی نیست. 10.77.10.1 را تا وقتی Resolver آن برای کلاینت‌ها آماده نشده به‌عنوان DNS اعلام نکنید. [راهنمای DNS](https://manual.mikrotik.com/docs/network-management/dns/) تنظیم سرویس پاسخ‌گویی را از صرف معرفی آدرس DNS جدا می‌کند.

## تبادل DHCP را چطور بخوانیم؟

کلاینت ابتدا برای یافتن سرور درخواست می‌فرستد، سرور پیشنهاد می‌دهد، کلاینت پیشنهاد را درخواست می‌کند و سرور آن را تأیید می‌کند. این چرخه را معمولاً با DISCOVER، OFFER، REQUEST و ACK می‌شناسیم. Lease مجوز استفادهٔ موقت از آدرس است؛ کلاینت پیش از انقضا برای تمدید تلاش می‌کند. خاموش شدن کلاینت لزوماً ردیف اجاره را همان لحظه حذف نمی‌کند.

[مرور رسمی DHCP](https://manual.mikrotik.com/docs/network-management/dhcp/) نقش کلاینت، سرور و Relay را توضیح می‌دهد. در این درس Relay نداریم و همهٔ اجزای تخصیص آدرس در همان LAB-LAN هستند. اگر کلاینت از سرور نامنتظره آدرس می‌گیرد، قبل از دست‌زدن به Pool، احتمال وجود سرور دوم یا اتصال اشتباه شبکهٔ مجازی را بررسی کنید.

## گام اول: موجودی و شرط شروع

در WinBox بخش IP → DHCP Server، IP → Pool و IP → Addresses را باز کنید. این فرمان‌ها معادل مشاهده هستند:

```routeros
/ip address print detail where interface=ether2
/ip pool print detail
/ip dhcp-server print detail
/ip dhcp-server network print detail
```

اگر از قبل DHCP Server روی ether2 یا Network همین زیرشبکه وجود دارد، دستورهای ساخت را تکرار نکنید. تنظیم موجود را با هدف این درس مقایسه کنید یا روی Snapshot تمیز تمرین کنید. وجود یک DHCP Server فعال دیگر در همان LAB-LAN باعث می‌شود موفق شدن دریافت آدرس به‌تنهایی عملکرد سرور R1 را ثابت نکند.

## گام دوم: سه جزء سرور را بسازید

در GUI، ابتدا در IP → Pool محدوده‌ای با نام `pool-l08` و بازهٔ 10.77.10.100-10.77.10.199 بسازید. سپس در DHCP Server بخش Networks شبکهٔ 10.77.10.0/24 و Gateway برابر 10.77.10.1 را اضافه کنید و ارسال DNS را در تنظیمات Network با dns-none=yes غیرفعال کنید؛ صرف خالی گذاشتن فیلد DNS کافی نیست. در نهایت یک DHCP Server با نام `dhcp-l08` روی ether2 بسازید، Pool را انتخاب و Lease Time را یک ساعت قرار دهید. تا بازبینی سه جزء، سرور را غیرفعال نگه دارید.

روش CLI جایگزین مراحل GUI است؛ هر دو روش را پشت سر هم اجرا نکنید:

```routeros
/ip pool add name=pool-l08 ranges=10.77.10.100-10.77.10.199
/ip dhcp-server network add address=10.77.10.0/24 gateway=10.77.10.1 dns-none=yes comment="TEHNET-L08-NET"
/ip dhcp-server add name=dhcp-l08 interface=ether2 address-pool=pool-l08 lease-time=1h disabled=yes
/ip dhcp-server print detail where name="dhcp-l08"
```

اکنون وجود آدرس ثابت ether2، Pool درست، Network درست و جدایی LAB-LAN را تأیید کنید. سپس فقط همین سرور را فعال کنید:

```routeros
/ip dhcp-server enable [find where name="dhcp-l08"]
```

خروجی مورد انتظار، فعال بودن سرور بدون علامت Invalid است. اگر Invalid دیدید، ابتدا علت را بررسی کنید؛ فایروال را دسته‌جمعی خاموش نکنید. [راهنمای DHCP Server](https://manual.mikrotik.com/docs/network-management/dhcp/server/) مرجع ارتباط Server، Pool و Network است.

## گام سوم: کلاینت و Lease را تأیید کنید

روی کلاینت آزمایشی فقط کارت LAB-LAN را روی دریافت خودکار IPv4 قرار دهید. در صورت نیاز رابط همان کارت را دوباره متصل یا اجاره را با ابزار سیستم‌عامل نوسازی کنید. تنظیم کارت مدیریت میزبان را تغییر ندهید. آدرس، ماسک، Gateway و سرور DHCP واقعی را از وضعیت شبکهٔ کلاینت بخوانید. مقدار مورد انتظار آدرسی در Pool، ماسک /24 و Gateway برابر 10.77.10.1 است.

در WinBox تب Leases را ببینید و MAC یا شناسهٔ کلاینت خود را تطبیق دهید. معادل CLI:

```routeros
/ip dhcp-server lease print detail where server="dhcp-l08"
```

وضعیت bound برای کلاینت متصل مورد انتظار است. سپس از کلاینت 10.77.10.1 را Ping کنید. آدرس داخل محدوده همراه با Gateway غلط، نتیجهٔ کامل محسوب نمی‌شود؛ Networks را بازبینی کنید. روی کلاینت نیز تنظیمات دستی قدیمی و کارت‌های دیگر می‌توانند مسیر متفاوت بسازند.

برای آشنایی با Static Lease، در GUI فقط اجارهٔ مربوط به همین کلاینت آزمایشی را با تطبیق MAC انتخاب و Make Static کنید. Static Lease به معنی ثبت یک واگذاری مشخص در سرور است، نه تنظیم IP ثابت دستی داخل کلاینت. قبل از انتخاب آدرس دلخواه، عدم تداخل آن را بررسی کنید. برای تمرین امروز نگه داشتن آدرس واگذارشده کافی است و نیازی به تغییر تصادفی آدرس ندارید.

## سناریوی جدا: DHCP Client روی WAN

این بخش فقط وقتی اجرا می‌شود که در LAB-WAN واقعاً DHCP Server بالادست ساخته‌اید. اگر قسمت هفتم را با WAN ثابت اجرا کردید، ابتدا آدرس دارای Comment `TEHNET-L07-WAN` و Default Route همان درس را پس از تأیید دقیق حذف کنید. آدرس LAN را دست نزنید. DHCP Client موجود روی ether1 را نیز بررسی کنید تا مورد دوم نسازید.

برای مشاهدهٔ دریافت تنظیمات بدون قبول خودکار DNS و مسیر پیش‌فرض، این الگو مناسب است:

```routeros
/ip dhcp-client add interface=ether1 add-default-route=no use-peer-dns=no disabled=no comment="TEHNET-L08-WANCLIENT"
/ip dhcp-client print detail where interface=ether1
```

خروجی مورد انتظار فقط با وجود بالادست درست، وضعیت bound و آدرس دریافتی شبکهٔ 10.77.0.0/24 است. در این الگو، Gateway پیش‌فرض به عمد اضافه نمی‌شود. DNS بالادست نیز پذیرفته نمی‌شود تا اثر هر تغییر مستقل دیده شود. [راهنمای DHCP Client](https://manual.mikrotik.com/docs/network-management/dhcp/client/) اثر add-default-route و use-peer-dns را توضیح می‌دهد. حالت searching بدون سرور بالادست طبیعی است و با راه‌اندازی DHCP Server روی WAN حل نمی‌شود.

## عیب‌یابی، تمرین و بازگشت

| نشانه | بررسی اول |
|---|---|
| کلاینت IP نامرتبط می‌گیرد | وجود DHCP دوم و اتصال اشتباه به شبکهٔ واقعی را بررسی کنید |
| کلاینت آدرس خودکار محلی می‌گیرد | فعال بودن سرور، رابط و لینک LAB-LAN را بررسی کنید |
| سرور Invalid است | آدرس ثابت رابط، انتخاب اینترفیس و وابستگی Pool را بررسی کنید |
| IP درست است ولی Gateway غلط | رکورد Network و تنظیم دستی کلاینت را ببینید |
| اینترنت و نام‌ها کار نمی‌کنند | در این درس راه‌اندازی نشده‌اند؛ معیار را با دریافت IP اشتباه نگیرید |

معیار قبولی، اجارهٔ bound متعلق به کلاینت درست، آدرس داخل Pool و Ping به R1 است. سناریوی WAN معیار جدا دارد و بدون وجود بالادست الزامی نیست. برای بازگشت، اول `dhcp-l08` را غیرفعال کنید، کلاینت آزمایشی را به وضعیت قبلی برگردانید و سپس فقط Leaseهای همین سرور، خود سرور، Network با Comment همین درس و Pool `pool-l08` را پس از بررسی وابستگی‌ها حذف کنید. DHCP Client دارای Comment همین درس را هم فقط اگر ساخته‌اید حذف کنید. آدرس مدیریت ether2 و سرویس‌های دیگر باید بر اساس دفترچهٔ تغییرات حفظ شوند؛ حذف همهٔ DHCPها روش بازگشت این تمرین نیست.
