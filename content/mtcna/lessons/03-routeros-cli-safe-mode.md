> پیش‌نویس مستقل تهنت؛ اجرای لابراتوار و ثبت تصویر هنوز انجام نشده است. خروجی‌های این متن «مورد انتظار» هستند، نه نتیجهٔ آزمون واقعی.

## پاسخ سریع و نتیجهٔ این قسمت

CLI همان تنظیمات RouterOS را با فرمان‌های متنی مدیریت می‌کند. مسیر ابتدای فرمان می‌گوید کدام بخش تغییر می‌کند؛ عمل و پارامترها مشخص می‌کنند چه اتفاقی می‌افتد. Safe Mode برای تغییرات کوچکِ قابل برگشت کمک می‌کند: اگر نشست مالک به‌طور غیرعادی قطع شود، تغییرات تحت پوشش پس گرفته می‌شوند. این قابلیت تضمین بازیابی پس از Reboot، Restore یا Reset نیست. تمرین امروز فقط نام روتر را موقتاً تغییر می‌دهد تا سازوکار را بدون دست‌زدن به مسیر مدیریت یاد بگیرید.

انتظار پایان درس این است که بتوانید تفاوت دستور مشاهده و تغییر را تشخیص دهید، پیش از حذف دقیقاً رکورد هدف را ببینید و دربارهٔ حفظ یا برگشت تغییر تصمیم آگاهانه بگیرید. به‌خاطر سپردن ده‌ها دستور هدف نیست. پیدا کردن مسیر درست، خواندن راهنما و کنترل محدودهٔ اثر، مهارت اصلی کار با کنسول است.

## پیش‌نیاز و محدودهٔ تمرین

R1 از قسمت دوم در LAB-LAN با آدرس 10.77.10.1 در دسترس است. کنسول ماشین مجازی را باز نگه دارید. فقط یک مدیر در این تمرین تنظیمات را تغییر دهد؛ Safe Mode می‌تواند تغییرات نشست‌های دیگر را هم زیر پوشش بگیرد و آزمایش چندنفره نتیجه را مبهم می‌کند. نام فعلی روتر را یادداشت کنید تا بعد بتوانید آن را دقیقاً برگردانید. اینجا هیچ اینترفیس، آدرس، کاربر یا قانون فایروالی حذف نمی‌شود.

برای ورود به ترمینال از New Terminal در WinBox یا کنسول VM استفاده کنید. صفحهٔ جاری [Console](https://manual.mikrotik.com/docs/management-tools/console/) مرجع رفتار نشست و کلیدهای کنسول است. ظاهر اعلان فرمان ممکن است با نام روتر و مسیری که در آن هستید فرق کند؛ متن اعلان را به‌عنوان فرمان کپی نکنید. فقط خود دستور داخل کادرهای این درس قابل ورود است.

## مسیر، عمل و پارامتر

در فرمان زیر `/system identity` مسیر، `print` عمل و خروجی آن نام فعلی دستگاه است:

```routeros
/system identity print
```

فرمان `/system identity set name=R1-TEHNET` یک تغییر است و نتیجه‌اش لزوماً متن مفصلی روی صفحه نیست. موفقیت را با `print` بررسی می‌کنیم. از اجرای آن فعلاً خودداری کنید؛ ابتدا تمرین Safe Mode را آماده می‌کنیم. این جداسازی مانع از آن می‌شود که یک نمونهٔ توضیحی را ناخواسته به مرحلهٔ اجرایی تبدیل کنید.

مسیر مطلق از `/` شروع می‌شود و از هر جای منو می‌توان آن را اجرا کرد. برای نمونه `/ip address print` همان بخش IP → Addresses را می‌خواند. اگر وارد یک منوی محلی شده باشید، دستور کوتاه در همان زمینه تفسیر می‌شود. در آموزش‌ها از مسیر کامل استفاده می‌کنیم تا وابستگی به موقعیت فعلی ترمینال کمتر شود. تکمیل با Tab و راهنمای تعاملی کنسول به پیدا کردن گزینه‌های معتبر کمک می‌کنند؛ نام پارامتر ناآشنا را از روی حدس ننویسید.

## خواندن قبل از نوشتن

این فرمان‌ها فقط برای مشاهده هستند:

```routeros
/system resource print
/interface print detail
/ip address print detail
/system identity print
```

خروجی مورد انتظار، فهرست واقعی ماشین خودتان است؛ تعداد ردیف‌ها یا پرچم‌ها را از یک تصویر اینترنتی تقلید نکنید. `detail` اطلاعات بیشتری از هر رکورد می‌دهد و `where` نمایش را محدود می‌کند. برای نمونه، دستور زیر فقط آدرس‌های ether2 را نشان می‌دهد:

```routeros
/ip address print detail where interface=ether2
```

شمارهٔ ردیف نمایش‌داده‌شده را شناسهٔ دائمی ندانید. مرتب‌سازی، فهرست‌گیری جدید یا تغییر داده‌ها می‌تواند آن را نامناسب کند. پیش از `set` یا `remove` با شرط روشن رکورد را پیدا کنید. شرط مبهم می‌تواند چند رکورد برگرداند و عمل روی همهٔ آن‌ها اعمال شود. [مرجع CLI](https://manual.mikrotik.com/docs/cli-reference/) برای بررسی نوع پارامتر و مسیر منو است؛ وجود پارامتر در مستندات شاخهٔ جدیدتر، دلیل پشتیبانی قطعی آن در نسخهٔ نصب‌شدهٔ شما نیست.

## تمرین اول: حفظ تغییر با Safe Mode

۱. با `/system identity print` نام فعلی را ثبت کنید. مطمئن شوید فرد دیگری هم‌زمان تغییر نمی‌دهد. سپس در همان ترمینال Ctrl+X یا F4 را بزنید. نشانهٔ مورد انتظار، اعلام گرفتن Safe Mode و وجود SAFE در اعلان است. در WinBox دکمهٔ Safe Mode نیز برای همین منظور وجود دارد؛ روش‌ها را در یک تمرین با هم مخلوط نکنید.

۲. نام را به مقدار موقت تغییر دهید و آن را بخوانید:

```routeros
/system identity set name=R1-TEHNET-CLI
/system identity print
/system history print
```

خروجی مورد انتظار، نام موقت و ثبت عمل در History است. این توصیف گزارش اجرای واقعی نیست. اگر نام عوض نشد، قبل از تکرار فرمان مجوز حساب و متن خطا را بررسی کنید. دستور درست را ده بار اجرا کردن روش تشخیص خطا نیست.

۳. برای نگه داشتن تغییر، دوباره Ctrl+X را در همان نشست بزنید تا Safe Mode آزاد شود. سپس نام را مجدداً بخوانید. آزاد کردن موفق Safe Mode با قطع اتفاقی ارتباط فرق دارد. نام موقت باید باقی بماند و اکنون با دستور مستقیم یا تمرین بعد قابل بازگشت است.

## تمرین دوم: برگشت عمدی و کم‌خطر

دوباره Safe Mode را بگیرید، نام را به `R1-TEHNET-ROLLBACK` تغییر دهید و نمایش را بررسی کنید. این بار در کنسول CLI با Ctrl+D نشست را ترک کنید تا تغییرهای Safe Mode لغو شوند. دوباره وصل شوید و نام را بخوانید. انتظار داریم نام پیش از این تمرین برگردد؛ اگر برنگشت، بررسی کنید Safe Mode واقعاً فعال بوده، چه کسی مالک آن بوده و نشست چگونه خاتمه یافته است.

برای این تمرین، کابل یا شبکهٔ مدیریت را عمداً قطع نکنید. قطع غیرعادی ممکن است تا تشخیص قطع نشست زمان ببرد و تازه‌کار را به تغییرهای اضافی سوق دهد. همچنین `/quit` را معادل Ctrl+D در رفتار Safe Mode فرض نکنید. [Configuration Management](https://manual.mikrotik.com/docs/getting-started/configuration-management/) روش حفظ و لغو تغییر و محدودیت History را توضیح می‌دهد.

## محدودیت‌ها و عیب‌یابی

تغییرات را کوچک نگه دارید. History ظرفیت محدودی دارد؛ یک Paste طولانی می‌تواند پوشش Safe Mode را از بین ببرد. عملیات نیازمند راه‌اندازی مجدد، از جمله Restore و Reset، آزمون مناسبی برای آن نیستند. وقتی یک تغییر دسترسی را تهدید می‌کند، علاوه بر Safe Mode باید مسیر کنسول و نسخهٔ پشتیبان هم داشته باشید.

| نشانه | معنی محتمل و اقدام |
|---|---|
| SAFE دیده نمی‌شود | مالکیت فعال نیست؛ قبل از تغییر دوباره وضعیت را روشن کنید |
| پیام مالک دیگر می‌آید | آزمایش را متوقف کنید و نشست‌های هم‌زمان را هماهنگ کنید |
| فرمان معتبر نیست | مسیر فعلی، نام عمل و نسخهٔ RouterOS را بررسی کنید |
| not enough permissions دیده می‌شود | مجوز حساب را بررسی کنید؛ کاربر را بی‌دلیل full نکنید |
| چند رکورد انتخاب می‌شوند | شرط where را دقیق‌تر کنید و ابتدا فقط print بگیرید |

## تمرین نهایی و بازگشت

بدون تغییر شبکه، آدرس‌های ether2 را فیلتر و نام فعلی را ثبت کنید. یک بار تغییر نام را حفظ و بار دیگر تغییر نام را لغو کنید. معیار پذیرش، دو نتیجهٔ متفاوت و توضیح کلید مورد استفاده است. نام اولیهٔ ثبت‌شده را در پایان از بخش System → Identity برگردانید. اگر از CLI استفاده می‌کنید، مقدار واقعی خودتان را داخل کوتیشن قرار دهید. نگه داشتن یک نام روشن مثل R1 برای ادامهٔ دوره مفید است، اما انتخاب نام نباید شما را از ثبت دقیق تغییرهای مهم‌تر بی‌نیاز کند.
