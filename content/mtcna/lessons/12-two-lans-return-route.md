> پیش‌نویس مستقل آموزشی تهنت، کوتاه‌شدهٔ تهران نتورک؛ اجرای آزمایشگاه و تهیهٔ تصاویر هنوز انجام نشده است. مبنای برنامه‌ریزی RouterOS 7.25.1 و WinBox 4.5 است؛ نمایش نسخهٔ 7.26 در مستندات جدید، تأیید اجرای این تمرین روی آن نسخه نیست. همهٔ نتیجه‌ها «مورد انتظار» هستند. این متن ادعای تطبیق با ویدئوی منتشرشده یا آزمون رسمی جدید ندارد.

## پاسخ سریع

برای ارتباط دو LAN، دانستن مسیر رفت کافی نیست؛ روتر سمت مقابل باید راه برگشت به شبکهٔ مبدأ را هم بداند. در این درس دو مسیر استاتیک متقابل می‌سازیم و NAT را وارد ارتباط داخلی نمی‌کنیم. با این روش، آدرس واقعی هر کلاینت در سمت مقابل دیده می‌شود و علت قطع ارتباط را می‌توان در جهت رفت و برگشت جداگانه بررسی کرد.

## هدف‌ها و پیش‌نیاز

انتظار می‌رود بتوانید لینک ترانزیت را از LAN تشخیص دهید، مسیرها را روی دستگاه درست وارد کنید و برای یک ping ناموفق، نقطهٔ شکست را محدود کنید. بریج LAN از درس ۱۰ و خواندن route از درس ۱۱ پیش‌نیاز است. هر دو روتر باید در آزمایشگاه جداشده و با کنسول قابل دسترس باشند. وجود فایروال پیش‌فرض یا قوانین قبلی را ثبت کنید؛ این درس مجوز حذف یا خاموش کردن آن‌ها نیست.

## جدول آدرس‌بندی

| نقش | رابط | آدرس |
|---|---|---|
| R1 LAN1 | bridge-lan | 10.77.10.1/24 |
| میزبان A | متصل به LAN1 | 10.77.10.10/24، گیت‌وی 10.77.10.1 |
| R1 ترانزیت | ether3 | 10.77.12.1/30 |
| R2 ترانزیت | ether1 | 10.77.12.2/30 |
| R2 LAN2 | ether2 | 10.77.20.1/24 |
| میزبان B | متصل به LAN2 | 10.77.20.10/24، گیت‌وی 10.77.20.1 |

ether1 در R1 همچنان WAN آزمایشگاهی است؛ ether1 در R2 در این طرح فقط لینک ترانزیت است. یکسان بودن نام پورت‌ها به معنی یکسان بودن نقش نیست. ether3 در R1 نباید عضو bridge-lan باشد. شبکهٔ /30 آدرس‌های میزبان .1 و .2 دارد؛ .0 شناسهٔ شبکه و .3 پخش است و به میزبان تخصیص نمی‌یابد.

## مراحل اجرا

۱. **پیش‌بررسی را روی هر دستگاه جدا انجام دهید.** از System > Identity یا عنوان پنجره مطمئن شوید کدام روتر را تغییر می‌دهید. IP > Addresses و Bridge > Ports را بخوانید. در R2 اگر ether1 عضو بریج پیش‌فرض یا دارای DHCP client است، این طرح روی آن پورت آمادهٔ اجرا نیست؛ ابتدا در نسخهٔ جداشدهٔ آزمایشگاه و از کنسول، تعارض را با تغییر محدود همان مورد رفع کنید. فرمان‌های زیر وضعیت مطلوب آزاد بودن پورت‌ها را فرض می‌کنند.

۲. **آدرس‌های ترانزیت را اضافه کنید.** در IP > Addresses، روی R1 و R2 ردیف جدا بسازید. آدرس LAN2 نیز فقط اگر از قبل موجود نیست اضافه شود. نباید دو آدرس یکسان با توضیح‌های متفاوت بسازید. در هر دو سمت، وضعیت لینک اترنت را پیش از ادامه ببینید.

**فقط روی R1:**

```routeros
/ip address add address=10.77.12.1/30 interface=ether3 comment="TEHNET-L12-r1-transit"
```

**فقط روی R2:**

```routeros
/ip address add address=10.77.12.2/30 interface=ether1 comment="TEHNET-L12-r2-transit"
/ip address add address=10.77.20.1/24 interface=ether2 comment="TEHNET-L12-r2-lan"
```

۳. **همسایهٔ مستقیم را آزمایش کنید.** روی R1، .2 را با مبدأ .1 ping کنید و در IP > ARP رابط ether3 را بررسی کنید. نتیجهٔ مورد انتظار پاسخ R2 است، مشروط به اجازهٔ ICMP ورودی روی آن. این مرحله هنوز LAN2 و کلاینت B را آزمایش نکرده است؛ صرف اتصال دو IP ترانزیت، راه شبکه‌های پشت روترها را خودکار معرفی نمی‌کند.

```routeros
# R1 only
/ping address=10.77.12.2 src-address=10.77.12.1 count=3
/ip arp print detail where interface=ether3
```

۴. **مسیر رفت و برگشت را بسازید.** در R1 مقصد LAN2 و گیت‌وی IP ترانزیت R2 است. در R2 مقصد LAN1 و گیت‌وی IP ترانزیت R1 است. در WinBox هر دستگاه از IP > Routes، Dst. Address و Gateway را با جدول تطبیق دهید. در این تمرین از default route برای پنهان کردن نبود مسیر مشخص استفاده نمی‌کنیم.

**فقط روی R1:**

```routeros
/ip route add dst-address=10.77.20.0/24 gateway=10.77.12.2 comment="TEHNET-L12-to-lan2"
/ip route print detail where comment="TEHNET-L12-to-lan2"
```

**فقط روی R2:**

```routeros
/ip route add dst-address=10.77.10.0/24 gateway=10.77.12.1 comment="TEHNET-L12-to-lan1"
/ip route print detail where comment="TEHNET-L12-to-lan1"
```

۵. **مبدأ آزمون را آگاهانه انتخاب کنید.** از R1 به IP LAN2 روتر با مبدأ LAN1 آزمایش کنید. سپس از میزبان A به گیت‌وی خودش، IP LAN2 روتر و در پایان میزبان B بروید. ping تولیدشده روی روتر با ترافیک عبوری کلاینت یکسان نیست؛ قواعد input و output با forward تفاوت دارند. اگر روترها همدیگر را می‌بینند ولی میزبان‌ها نه، همین تفاوت یک سرنخ است.

```routeros
# R1 only
/ping address=10.77.20.1 src-address=10.77.10.1 count=3
```

نتیجهٔ مورد انتظار نهایی، رسیدن A به B با حفظ مبدأ 10.77.10.10 است. فایروال خود B باید ICMP آزمایش را از LAN1 مجاز بداند؛ خاموش کردن کلی فایروال میزبان راه تشخیص لازم نیست. اگر NAT عمومی از درس دیگری باقی مانده، شرط out-interface آن را بررسی کنید تا ناخواسته لینک ether3 را هم ترجمه نکند.

۶. **نقش مسیر برگشت را بدون دستکاری گسترده ثابت کنید.** در کنسول R2 فقط مسیر دارای توضیح این درس را موقتاً disable کنید، یک ping تازه از A به B بگیرید و سپس آن مسیر را enable کنید. اگر R2 مسیر جایگزین دارد، نتیجه ممکن است متفاوت باشد؛ پیش از تفسیر، جدول کامل را بخوانید. این تمرین فقط روی مسیر آزمایشگاهی و از دسترسی محلی انجام می‌شود.

```routeros
# R2 only
/ip route disable [find where comment="TEHNET-L12-to-lan1"]
/ip route enable [find where comment="TEHNET-L12-to-lan1"]
```

## جدول عیب‌یابی

| نشانه | بررسی بعدی | احتمال |
|---|---|---|
| دو IP ترانزیت ارتباط ندارند | اتصال ether3 R1 به ether1 R2 و /30 | خطای لینک یا input |
| R1 به LAN2 روتر می‌رسد اما A نمی‌رسد | forward و گیت‌وی A | آزمون روتر و عبور متفاوت‌اند |
| درخواست به B می‌رسد، پاسخ برنمی‌گردد | گیت‌وی B و مسیر R2 به LAN1 | مسیر برگشت یا فیلتر میزبان |
| همه چیز از مبدأ ترانزیت درست است | آزمون با src-address LAN1 | مسیر شبکهٔ واقعی مبدأ ممکن است مفقود باشد |

## تمرین، پذیرش و بازگشت

برای یک بستهٔ A به B، در هر گام مقصد IP ثابت و next-hop متغیر را بنویسید. سپس همین کار را برای پاسخ انجام دهید. پذیرش تمرین به دو مسیر فعال، گیت‌وی صحیح دو کلاینت و توضیح هر دو جهت نیاز دارد؛ پاسخ ping ترانزیت به‌تنهایی کافی نیست. برای بازگشت، فقط موارد زیر را روی روتر مشخص‌شده حذف کنید و LAN1 اصلی را نگه دارید.

**فقط روی R1:**

```routeros
/ip route remove [find where comment="TEHNET-L12-to-lan2"]
/ip address remove [find where comment="TEHNET-L12-r1-transit"]
```

**فقط روی R2:**

```routeros
/ip route remove [find where comment="TEHNET-L12-to-lan1"]
/ip address remove [find where comment="TEHNET-L12-r2-transit"]
/ip address remove [find where comment="TEHNET-L12-r2-lan"]
```
