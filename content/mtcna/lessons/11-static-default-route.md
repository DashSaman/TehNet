> پیش‌نویس مستقل آموزشی تهنت، کوتاه‌شدهٔ تهران نتورک؛ اجرای آزمایشگاه و تهیهٔ تصاویر هنوز انجام نشده است. مبنای برنامه‌ریزی RouterOS 7.25.1 و WinBox 4.5 است؛ نمایش نسخهٔ 7.26 در مستندات جدید، تأیید اجرای این تمرین روی آن نسخه نیست. همهٔ نتیجه‌ها «مورد انتظار» هستند. این متن ادعای تطبیق با ویدئوی منتشرشده یا آزمون رسمی جدید ندارد.

## پاسخ سریع

مسیر استاتیک به روتر می‌گوید برای رسیدن به یک شبکه، بسته را به کدام گام بعدی بسپارد. مسیر پیش‌فرض با مقصد 0.0.0.0/0 برای مقصدهایی کاربرد دارد که مسیر مشخص‌تری ندارند. وجود این ردیف در جدول به‌تنهایی اینترنت نمی‌سازد؛ گیت‌وی باید قابل دسترسی باشد و مسیر برگشت، سرویس مقصد و سیاست عبور هم درست باشند. این درس روی یک بالادست آزمایشگاهی کار می‌کند، نه روی اتصال واقعی مشترک اینترنت.

## هدف‌ها و پیش‌نیاز

پس از مطالعه باید بتوانید از روی جدول، شبکه‌های مستقیماً متصل را پیدا کنید، تفاوت آدرس مقصد و next-hop را توضیح دهید و دلیل بی‌اثر بودن یک مسیر غیرفعال را بررسی کنید. پیش‌نیاز، subnet و بریج درس قبل است. NAT در این درس اضافه نمی‌شود. اگر شبکهٔ آزمایشگاهی شما بالادست ندارد، بخش مشاهده و تحلیل را انجام دهید و فرمان ساخت مسیر پیش‌فرض را اجرا نکنید؛ ساختن یک گیت‌وی خیالی، جای فراهم کردن شبکه را نمی‌گیرد.

## آدرس‌بندی آزمایشگاه

R1 روی bridge-lan آدرس 10.77.10.1/24 دارد و میزبان LAN برابر 10.77.10.10/24 با گیت‌وی 10.77.10.1 است. فقط اگر سگمنت بالادست جداشده واقعاً موجود باشد، ether1 روتر به آن متصل و آدرس آزاد 10.77.0.2/24 به R1 اختصاص می‌یابد. گیت‌وی آن سگمنت 10.77.0.1 است. پیش از اختصاص .2 بررسی کنید با DHCP یا دستگاه دیگری تداخل نداشته باشد. ether3 و ether4 را برای این اتصال جابه‌جا نکنید؛ ether3 برای لینک بین روترها در درس بعد محفوظ است.

## مراحل اجرا

۱. **جدول را پیش از افزودن مسیر بخوانید.** در WinBox، IP > Routes را باز کنید. مقصد، Gateway، Distance و فلگ‌ها را کنار هم بخوانید. یک شبکهٔ متصل از IP فعال روی رابط به دست می‌آید و نباید برای همان شبکه، مسیر استاتیک تکراری بسازید. وضعیت اولیهٔ default route را ثبت کنید؛ ممکن است DHCP client از قبل مسیر پیش‌فرض پویا ساخته باشد.

```routeros
/ip address print detail
/ip route print detail
/ip dhcp-client print detail where interface=ether1
```

در این تمرین، اگر ether1 از قبل توسط DHCP مدیریت می‌شود یا default route فعال دیگری وجود دارد، توقف در مرحلهٔ بازبینی یک نتیجهٔ درست است. بدون طراحی سازگار، آدرس استاتیک و مسیر دوم اضافه نکنید. هدف، دیدن رابطهٔ روشن بین یک گیت‌وی و یک خروجی است، نه ساخت چند مسیر هم‌ارزش و سپس حدس زدن علت رفتار آن‌ها.

اگر شاخهٔ اختیاری WAN درس ۷ را اجرا کرده‌اید، آدرس 10.77.0.2/24 و مسیر پیش‌فرض منطبق را پس از بررسی دوباره استفاده کنید و فرمان‌های add این درس را برای آن‌ها اجرا نکنید. راه دیگر، بازگشت محدود و مستند همان درس ۷ پیش از ساخت ردیف‌های درس ۱۱ است. تنها برای داشتن Comment تازه، آدرس یا مسیر تکراری نسازید. در حالت استفادهٔ دوباره، فرمان print را با آدرس و مقصد موجود تطبیق دهید و هنگام بازگشت، تنظیم متعلق به درس ۷ را حذف نکنید.

۲. **آدرس بالادست را فقط در شاخهٔ استاتیک بسازید.** شرط اجرای فرمان زیر آزاد بودن ether1 از تنظیم متعارض و وجود واقعی بالادست است. در IP > Addresses، Address و Interface را وارد کنید و توضیح مشخص بدهید. سپس گیت‌وی مستقیم را با مبدأ همان شبکه آزمایش کنید.

```routeros
/ip address add address=10.77.0.2/24 interface=ether1 comment="TEHNET-L11-wan-address"
/ping address=10.77.0.1 src-address=10.77.0.2 count=3
/ip arp print detail where address=10.77.0.1
```

نتیجهٔ مورد انتظار، دسترسی مستقیم به .1 در صورت مجاز بودن ICMP و ایجاد همسایهٔ آن روی ether1 است. اگر ping پاسخ ندارد ولی ARP کامل است، مسئله را فوراً نبود مسیر ننامید؛ ممکن است میزبان گیت‌وی ICMP را پاسخ ندهد. اگر ARP هم کامل نمی‌شود، کابل، سگمنت و آدرس بالادست را پیش از افزودن route بررسی کنید.

۳. **مسیر پیش‌فرض را اضافه کنید.** در IP > Routes گزینهٔ افزودن را بزنید؛ Dst. Address برابر 0.0.0.0/0 و Gateway برابر 10.77.0.1 و Distance برابر 1 است. مقصد مسیر، نام رابط یا آدرس LAN نیست. در شبکهٔ اترنت معمول، برای گیت‌وی دور از IP گام بعدی استفاده کنید؛ صرفاً نوشتن ether1 برای همهٔ مقصدهای دور باعث نمی‌شود همسایهٔ درست معلوم شود.

```routeros
/ip route add dst-address=0.0.0.0/0 gateway=10.77.0.1 distance=1 comment="TEHNET-L11-default"
/ip route print detail where comment="TEHNET-L11-default"
```

نتیجهٔ مورد انتظار، مسیر انتخاب‌پذیر و در شرایط این طرح، فعال است. از روی حرف فعال نتیجه نگیرید که وب‌سایت باز می‌شود. روتر می‌تواند راه سپردن بسته به next-hop را بداند، ولی next-hop خودش خروجی یا مسیر برگشت نداشته باشد. بررسی وضعیت و آزمون سرویس دو سطح جدا از شواهد هستند.

۴. **مسیر مشخص‌تر را ذهنی مقایسه کنید.** مقصد 10.77.10.10 در شبکهٔ متصل LAN است؛ مسیر پیش‌فرض نباید آن را به بالادست بفرستد. برای مقصد بیرون از شبکه‌های شناخته‌شده، مسیر پیش‌فرض نامزد می‌شود. Distance برای مقایسهٔ مسیرهای رقیب مناسب است؛ عدد کمتر یک default route را بر مسیر متصل با پیشوند مشخص‌تر غالب نمی‌کند. برای این تحلیل نیاز نیست آدرس عمومی تصادفی ping کنید.

۵. **آزمون را با مبدأ تکرار کنید.** پاسخ گیت‌وی به مبدأ 10.77.0.2 فقط همان شبکهٔ متصل را می‌سنجد. اگر با مبدأ 10.77.10.1 آزمایش کنید، بالادست باید راه برگشت به LAN1 را داشته باشد. نبود پاسخ دوم همراه با موفقیت اول می‌تواند از نبود همین راه برگشت باشد؛ ساخت NAT فوری، علت را از دید پنهان می‌کند. این بررسی مقدمهٔ درس بعد است.

```routeros
/ping address=10.77.0.1 src-address=10.77.10.1 count=3
```

## جدول عیب‌یابی

| نشانه | بررسی بعدی | نتیجهٔ قابل دفاع |
|---|---|---|
| مسیر پیش‌فرض غیرفعال | آدرس و وضعیت ether1، next-hop | فقط افزودن دوباره درمان نیست |
| دو default route دیده می‌شود | DHCP client و توضیح مسیرها | احتمال وجود تنظیم قبلی یا مسیر پویا |
| گیت‌وی با مبدأ WAN پاسخ می‌دهد | آزمون برگشت برای LAN | هنوز عبور کلاینت اثبات نشده است |
| LAN محلی به بالادست فرستاده می‌شود | ماسک و مسیر متصل | طرح آدرس یا رابط باید بازبینی شود |

## تمرین و معیار پذیرش

سه مقصد انتخاب کنید: خود روتر، میزبان LAN و یک میزبان واقعی آزمایشگاه در پشت بالادست که مدیر آن معرفی کرده است. پیش از آزمون بنویسید روتر برای هرکدام چه تصمیمی می‌گیرد و برگشت از کدام مسیر ممکن می‌شود. اگر میزبان سوم فراهم نیست، آن ردیف را «اجرا نشد» علامت بزنید. موفقیت یعنی توانایی توضیح مسیر انتخابی و محدودیت مدرک، نه ثبت پاسخ ساختگی از اینترنت.

## بازگشت محدود

فقط default route و آدرس ساخته‌شدهٔ همین شاخه را حذف کنید؛ مسیر پویا و آدرس قبلی متعلق به این تمرین نیست. پس از حذف، وجود مسیر LAN و دسترسی محلی را دوباره بررسی کنید.

```routeros
/ip route remove [find where comment="TEHNET-L11-default"]
/ip address remove [find where comment="TEHNET-L11-wan-address"]
```
