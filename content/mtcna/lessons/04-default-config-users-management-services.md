> پیش‌نویس مستقل تهنت؛ اجرای لابراتوار و ثبت تصویر هنوز انجام نشده است. خروجی‌های این متن «مورد انتظار» هستند، نه نتیجهٔ آزمون واقعی.

## پاسخ سریع و نتیجهٔ این قسمت

برای آماده کردن روتر، اول وضع موجود را می‌خوانیم، سپس یک حساب جایگزین می‌سازیم و ورود آن را در نشست دوم امتحان می‌کنیم. بعد سرویس‌هایی را که استفاده نمی‌کنیم به‌صورت جداگانه غیرفعال می‌کنیم. Reset یا حذف همهٔ قوانین فایروال روش شروع این درس نیست. پایان کار باید بدانید چه حسابی مدیریت می‌کند، کدام سرویس برای اتصال لازم است و در صورت اشتباه از کدام کنسول برمی‌گردید.

«پیکربندی پیش‌فرض MikroTik» یک فایل ثابت برای همهٔ دستگاه‌ها نیست. مدل، شیوهٔ نصب و نوع محصول بر تنظیمات آغازین اثر دارند. CHR را هم‌ارز یک روتر خانگی با آدرس 192.168.88.1، DHCP و فایروال آماده ندانید. در [مستند تنظیمات پیش‌فرض](https://manual.mikrotik.com/docs/getting-started/configuration-management/default-configurations/) تفاوت سناریوهای دستگاه‌ها آمده است. دادهٔ واقعی R1 مرجع این لابراتوار است.

## پیش‌نیاز و مرز دسترسی

رایانهٔ مدیریت روی LAB-LAN آدرس 10.77.10.10/24 دارد و R1 روی ether2 آدرس 10.77.10.1/24. ether1 همچنان فقط به بالادست جدا یا شبکهٔ قطع‌شده وصل است. کنسول VM و یک نشست WinBox فعال داشته باشید. رمز حساب موجود را در اختیار داشته باشید و هنوز آن حساب را حذف یا غیرفعال نکنید. این درس طرح کامل فایروال را جایگزین نمی‌کند؛ تا آماده شدن سیاست فایروال، جدایی شبکهٔ مجازی شرط اصلی محیط است.

در این دوره تا معرفی Bridge در قسمت دهم، مدیریت LAN روی ether2 انجام می‌شود. اگر روی ماشین دیگری تمرین می‌کنید که آدرس روی bridge است، دستورها را کورکورانه اجرا نکنید. هدف آموزشی را به نقشهٔ واقعی آن محیط تطبیق دهید یا به Snapshot تمیز R1 برگردید. تغییر هم‌زمان ساختار Bridge و حساب‌ها، تشخیص علت قطع ارتباط را دشوار می‌کند.

## گام اول: موجودی بگیرید

در WinBox بخش‌های IP → Addresses، IP → Services، System → Users و IP → Firewall را مشاهده کنید. برای ثبت متنی از این فرمان‌ها استفاده کنید:

```routeros
/system identity print
/user print detail
/ip service print detail
/ip address print detail
/ip firewall filter print
/ip firewall nat print
```

خروجی مورد انتظار، فهرست واقعی تنظیمات است؛ خالی بودن فایروال در CHR را با وجود حفاظت پیش‌فرض اشتباه نگیرید. خروجی حاوی نام کاربر، آدرس مدیریت یا شناسهٔ دستگاه می‌تواند برای انتشار عمومی نامناسب باشد؛ قبل از تهیهٔ تصویر آموزشی آن را بازبینی کنید. هدف این موجودی، داشتن نقطهٔ مقایسه قبل و بعد است، نه نمایش اطلاعات محرمانه.

از جدول سرویس‌ها نام، پورت و وضعیت enabled/disabled را بنویسید. WinBox، SSH، وب و API راه‌های مدیریت متفاوت هستند. تغییر پورت به‌تنهایی جای رمز قوی، محدودیت مبدأ یا فایروال را نمی‌گیرد. همچنین غیرفعال کردن سرویس IP لزوماً همهٔ روش‌های مدیریت لایهٔ دوم را تغییر نمی‌دهد؛ MAC WinBox موضوع جداگانه‌ای است که باید در سیاست دسترسی دیده شود.

## گام دوم: حساب جایگزین بسازید

در System → Users یک حساب محلی با نامی مثل `lab-admin` و گروه `full` بسازید. این گروه برای تمرین مدیریت کامل انتخاب شده است، نه به‌عنوان سطح مناسب همهٔ کارکنان. یک رمز طولانی و یکتا وارد کنید؛ رمز نمونهٔ مقاله را رمز واقعی قرار ندهید. برای ناظر صرف، گروه با دسترسی کمتر مناسب‌تر است، اما نام گروه به‌تنهایی کافی نیست و سیاست‌های آن باید بررسی شود. [مرجع User](https://manual.mikrotik.com/docs/authentication-authorization-accounting/user/) توضیح مجوزها و محدودیت ورود را دارد.

در صورت استفاده از CLI، ابتدا وجود نام را بررسی کنید:

```routeros
/user print detail where name="lab-admin"
```

فقط اگر چنین حسابی وجود ندارد، الگوی زیر را با رمز شخصی خود اجرا کنید. رشتهٔ داخل کوتیشن باید پیش از اجرا عوض شود؛ اگر از History یا اشتراک صفحه نگرانید، ساخت رمز را در پنجرهٔ گرافیکی انجام دهید.

```routeros
/user add name=lab-admin group=full password="REPLACE-WITH-YOUR-UNIQUE-PASSWORD" comment="TEHNET-L04"
```

اکنون نشست اول را باز نگه دارید. در پنجرهٔ دوم WinBox با `lab-admin` به 10.77.10.1 وصل شوید و `/system resource print` را اجرا کنید. معیار قبولی، ورود واقعی با حساب جدید و امکان مشاهدهٔ اطلاعات است؛ دیدن ردیف کاربر در فهرست به معنی درست بودن رمز نیست. یک بار خارج و دوباره وارد شوید تا اشتباه تایپ یا استفادهٔ ناخواسته از حساب ذخیره‌شده روشن شود.

پس از این تأیید و در حالی که کنسول و حساب جدید آماده‌اند، اگر حسابی دقیقاً به نام `admin` وجود دارد، می‌توانید آن را غیرفعال کنید. ابتدا `/user print detail where name="admin"` را ببینید و سپس فقط همان حساب را از GUI غیرفعال کنید. غیرفعال‌کردن برگشت‌پذیر است و در این درس نیازی به حذف حساب نداریم. اگر نام دیگری حساب اولیه بوده، روی نام فرضی عملی انجام ندهید.

## گام سوم: سرویس را هدفمند محدود کنید

WinBox مورد استفادهٔ خود را فعال نگه دارید. اگر Telnet و FTP در موجودی فعال هستند و هیچ بخشی از تمرین به آن‌ها وابسته نیست، از IP → Services فقط همان دو سرویس را غیرفعال کنید. معادل CLI:

```routeros
/ip service disable [find where name="telnet"]
/ip service disable [find where name="ftp"]
/ip service print detail
```

این دستورها بر اساس نام انتخاب می‌کنند و سرویس وب یا WinBox را خاموش نمی‌کنند. با این حال، فهرست قبل و بعد را مقایسه کنید. اگر از FTP برای دانلود Backup استفاده می‌کردید، ابتدا روش دریافت فایل از WinBox را آماده کنید. برای هر سرویس، وابستگی واقعی را بررسی کنید و سپس آن را خاموش کنید.

محدود کردن مبدأ سرویس به شبکهٔ مدیریت قدم مفیدی است، ولی نام پارامتر در نسخه‌های مستندات و نرم‌افزار ممکن است فرق کند. در این نسخهٔ پیش‌نویس، ابتدا محدودیت شبکهٔ مجازی را حفظ و تنظیم IP Services را از GUI بر اساس امکانات نسخهٔ نصب‌شده بررسی کنید. پارامتر راهنمای جاری را بدون بررسی روی 7.25.1 Paste نکنید. [راهنمای امن‌سازی رسمی](https://manual.mikrotik.com/docs/getting-started/securing-your-router/) اصول حساب و سرویس را توضیح می‌دهد. این محدودیت‌ها جای Firewall Input را نمی‌گیرند.

## عیب‌یابی و تحلیل نتیجه

| نشانه | بررسی و راه برگشت |
|---|---|
| حساب جدید وارد نمی‌شود | رمز، نام، گروه و محدودیت مبدأ آن را از نشست اول بررسی کنید |
| ورود WinBox قطع شده است | در کنسول وضعیت سرویس winbox و آدرس LAN را ببینید |
| حساب admin دیده نمی‌شود | نام فرضی نسازید؛ موجودی واقعی کاربران را بررسی کنید |
| سرویس از قبل خاموش بود | این رفتار خطا نیست؛ تغییر اضافه لازم ندارید |
| پورت متفاوت است | مقدار واقعی IP Services را در مقصد اتصال وارد کنید |

## تمرین، تأیید و بازگشت

جدولی با سه ستون «قبل»، «بعد» و «دلیل» برای حساب‌ها و سرویس‌ها بسازید. باید بتوانید با حساب جدید دوباره وارد شوید، سرویس WinBox فعال باقی بماند و Telnet و FTP در صورت استفاده‌نشدن خاموش باشند. هیچ تستی از اینترنت عمومی انجام ندهید. بررسی مدیریتی از همان LAB-LAN انجام می‌شود و ثابت نمی‌کند روتر برای تولید آماده است.

برای بازگشت، با حساب مدیریتی کارآمد یا کنسول، حساب اولیهٔ مورد نظر را دوباره فعال کنید. فقط سرویس‌هایی را که واقعاً در این درس خاموش کرده‌اید و برای ادامه لازم هستند فعال کنید؛ مثلاً `/ip service enable [find where name="ftp"]` صرفاً وقتی FTP پیش‌تر فعال و مورد نیاز بوده است. حساب جایگزین را تا اطمینان از مسیر ورود دیگر حذف نکنید. بخش [اطلاعات و ابزارهای سیستم](https://manual.mikrotik.com/docs/system-information-and-utilities/) مسیر مرجع سرویس‌ها و فایل‌ها را برای مرور بیشتر ارائه می‌کند.
