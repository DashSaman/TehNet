# معماری فروشگاه و عملیات

دامنه و مسیر /shop حفظ می‌شوند. قالب فقط نمایش را انجام می‌دهد. منطق فروش در افزونه جداگانه TehNet Store قرار می‌گیرد تا Core زنده 0.3.1 و quote/invoiceهای قبلی بدون بازنویسی حفظ شوند.

WooCommerce مرجع سبد/سفارش و حساب مشتری است؛ ERPNext مرجع موجودی فیزیکی، رزرو و GL است. پیش‌فاکتورهای CPT قبلی سند دفتر کل نیستند. یک قلم فقط یک stock UOM دارد: کابل متر؛ خرید قرقره با conversion معتبر و ثبت ضایعات از همان موجودی، بدون شمارش دوباره.

پول در مرز اتصال عدد صحیح IRR و در UI با برچسب واحد صریح است. تومان دقیقاً تقسیم بر ۱۰ است؛ مقدار ناسازگار به‌جای گردکردن پنهان رد می‌شود. مقدار کابل رشته decimal با تبدیل دقیق در ERP است و float مبنای محاسبه مالی نیست.

رویداد Woo دارای کلید immutable و payload hash است. Outbox بعد از ذخیره سفارش ارسال می‌شود. مقصد درخواست تکراری یکسان را idempotent قبول و کلید تکراری با payload متفاوت را رد می‌کند. timeout نتیجه نامعلوم است و نیاز reconciliation دارد؛ هیچ پاسخ نمایشی مرورگر اثبات پرداخت نیست.

چرخه هدف: استعلام → quotation → تأیید قیمت/موجودی → sales order و رزرو تراکنشی → پرداخت server-verified → preparation/pick/pack → delivery → invoice/payment entry → settlement. لغو رزرو را آزاد می‌کند؛ مرجوعی جزئی به سطر سفارش و stock return/credit note مرتبط است. ثبت مالی فقط توسط ERP و با توازن بدهکار/بستانکار؛ اصلاح سند ثبت‌شده با برگشت.

هیچ credential واقعی در نمونه‌ها وجود ندارد. پرداخت، SMS، ارسال و connector بدون credential روشن و غیرفعال‌اند. مسیر آزمون، localhost و داده ساختگی صریحاً sandbox است؛ داده منبع، موجودی یا قیمت تهران نتورک نیست.

کاتالوگ اولیه draft، بدون قیمت و stock=0 است. source URL/ID در meta، SKU مستقل TN-SN-ID، ویژگی‌های مشاهده‌شده همراه وضعیت «تأییدنشده». تصویر/توضیح اختصاصی منبع کپی نمی‌شود؛ تصویر جایگزین خود فروشگاه و متن اصیل استفاده می‌شود. هیچ امتیاز/نظر/واترمارک منتقل یا دستکاری نمی‌شود. تناقض فنی مانع انتشار است.

قانونی: دریافت اطلاعات و اتصال سامانه مودیان/شناسه‌های مالیاتی، تابع اسناد رسمی و اعتبارنامه مالک است. جست‌وجوی رسمی این اجرا سند نسخه‌دار قابل استناد برنگرداند؛ نرخ/قالب صورتحساب یا انطباق قانونی به‌صورت حدسی اعمال نمی‌شود.

## ادامه پرداخت آزمایشی — ۱۵ اکتبر ۲۰۲۶

ماژول `TehNet_Store_Zarinpal_Sandbox` فقط محیط local/staging و محصولات صریحاً synthetic را می‌پذیرد. API ثابت sandbox، IRR صحیح، attempt/receipt ماندگار، token اختصاصی callback، قفل سفارش و data-store refresh پس از verify، کنترل receipt مشترک و recovery پاسخ101 اعمال شده است. Woo gateway و Blocks registry فقط پوسته همین سرویس‌اند؛ ERP همچنان مرجع reservation/GL است. flags آزمایش و ERP sandbox باید سمت سرور فعال باشند و UI درگاه نیز جداگانه فعال شود؛ پیش‌فرض همه خاموش است.

این آداپتور آزمایشی مسیر production ندارد و برای استفاده واقعی توصیه/تأیید نشده است؛ سند دامنه و شواهد مستقل/native در docs/payment-sandbox-fa.md است.
