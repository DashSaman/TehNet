# مدیریت تصاویر و نمای ۳۶۰

## منبع و وضعیت

برای ۲۵ SKU موجود، ۳۰ ارجاع تصویر از API عمومی سعید شبکه بازبینی شده است (۲۳ فایل یکتا). مالک در همین گفتگو اجازه استفاده تجاری را تأیید کرد. فایل‌ها و هش آن‌ها در `content/media/saieedshabake-2026-10-16` ثبت‌اند. تأیید منشأ عکاسی و تطبیق مدل سازنده، مستقل از مالکیت رسانه، همچنان باز است. همه اقلام در حالت استعلام می‌مانند.

نشان کم‌رنگ `tehnet.ir` روی کارت، گالری و نمایشگر عکس‌محور سایت دیده می‌شود. این نشان یک لایهٔ نمایشی است؛ در دانلود مستقیم تصویر حک نشده است. با درخواست صریح تازهٔ مالک، نوشتهٔ فروشنده از ۱۵ فایل دارای نوشته پاک‌سازی می‌شود؛ اصل ۲۳ فایل برای حسابرسی و بازگشت حفظ می‌شود. جزئیات و علائم سازنده از تصویر اصلی برگردانده شده‌اند؛ تولید محصول یا زاویهٔ تخیلی انجام نشده است.

نسخه‌های پاک‌سازی در `content/media/tehnet-clean-2026-10-16` همراه با manifest و وصله‌های شفاف هستند. ابزار داخلی imagegen پس‌زمینه را بازسازی کرد و compositor اصل RGB را بیرون ماسک بازبینی‌شده حفظ کرد. دستور `node ops/verify-clean-catalog-images.cjs` بازتولید دقیق ۱۵ تصویر و صفر تغییر بیرون ماسک را بررسی می‌کند. بازبینی بصری ماسک، مستقل از این آزمون پیکسلی لازم است.

## اجرای امن رسانه

واردسازی عادی کاتالوگ همچنان هیچ رسانه‌ای وارد نمی‌کند. مهاجرت تصاویر مسیر جدا دارد:

```
python ops/release-catalog-photos.py prepare
python ops/release-catalog-photos.py apply
```

prepare فقط فایل‌های انتشار را در مسیر خصوصی سرور آماده می‌کند و dry run وردپرس را می‌خواند. apply پیش از تغییر، پشتیبان کامل همان تولید می‌گیرد و checksum آن را بررسی می‌کند. بعد از اجرا، دوباره apply می‌شود تا صفر تغییر و ۲۵ skip ثابت شود. قیمت، موجودی، عنوان، وضعیت، تعداد سفارش‌ها و محتوای خانه با snapshot قبل مقایسه می‌شوند. نتیجه در `qa/store-2026-10-16/photos-apply.json` ثبت می‌شود. هنگام اختلاف، خطا را بررسی کنید؛ قفل یا رسید را کورکورانه حذف نکنید.

```
python ops/release-catalog-photos.py rollback
```

rollback فقط ارجاع‌های رسانهٔ همین انتشار را برمی‌گرداند؛ اگر مدیر بعداً عکس/گالری را تغییر داده باشد، عملیات متوقف می‌شود. عکس‌های ایجادشده حذف نمی‌شوند و برای بازیابی باقی می‌مانند. این دستور روی تولید فقط بعد از بررسی علت و وضعیت فعلی اجرا شود.

## جایگزینی نسخهٔ پاک‌سازی‌شده

پس از تأیید `reviewed=true` در manifest، مسیر مستقل زیر ۱۵ فایل را روی ۱۱ محصول جایگزین می‌کند. ۱۴ محصول دیگر دست‌نخورده می‌مانند. SHA اصل، تعلق attachment، ترتیب گالری و نبود تغییر انسانی پیش از هر نوشتن بررسی می‌شوند.

```
python ops/release-catalog-photos.py prepare --cleanup
python ops/release-catalog-photos.py apply --cleanup
```

این مسیر backup کامل تازه و checksum، تطبیق فیلدهای تجاری/خانه و اجرای مجدد صفر تغییر/۲۵ skip دارد. شواهد در `qa/store-2026-10-16/cleanup-apply.json` ثبت می‌شوند. فایل اصلی حذف یا overwrite نمی‌شود؛ attachment تازهٔ WebP ساخته و فقط ارجاع محصول عوض می‌شود. در صورت نیاز به بازگشت همین مرحله:

```
python ops/release-catalog-photos.py rollback --cleanup
```

این بازگشت، گالری اصلیِ پیش از پاک‌سازی را برمی‌گرداند و هر دو نسخه را نگه می‌دارد. پس از پاک‌سازی، importer قدیمی را دوباره apply نکنید؛ کنترل اختلاف رسانه باید آن را متوقف کند. اگر مدیر بعداً رسانه را تغییر داده، رسید یا قفل را حذف نکنید و تغییر را ابتدا بررسی کنید.

## ادامهٔ واقعی ۳۶۰

مجموعه فعلی حداکثر دو عکس متفاوت برای هر محصول دارد و نمای کامل ۳۶۰ نیست. روی این محصولات نمایشگر شماتیک قدیمی کنار گذاشته شده است؛ نبودِ نمای ۳۶۰ صریحاً نوشته می‌شود. تصاویر منبع ممکن است رندر شده باشند؛ آن‌ها را عکس عکاسی‌شده یا مدل سه‌بعدی واقعی نمی‌نامیم.

برای هر مدل، ابتدا شماره فنی را با خود کالا تطبیق دهید. از همان نمونه روی پایه گردان، با نور، فاصله، زمینه و ارتفاع ثابت، دست‌کم ۲۴ عکس در یک دور کامل با فاصله ۱۵ درجه بگیرید. اندازه و جهت قاب را ثابت نگه دارید؛ عکس‌ها را به ترتیب زاویه نام‌گذاری کنید. رنگ، پورت‌ها، اتصالات و برچسب‌های کالا باید در تصاویر دیده شوند. از یک عکس، پشت محصول را تولید نکنید. ۱۲ فریم حداقل فنی نمایشگر است و جای پوشش و کیفیت بازبینی‌شده را نمی‌گیرد.

عکس‌های اصلی را از صفحه ویرایش همان محصول در رسانهٔ وردپرس بارگذاری کنید. پس از بازبینی پوشش کامل، ترتیب، تعلق و مجوز، مسئول فنی شناسه‌های attachment را به‌ترتیب در متادیتای `_tn_spin_attachment_ids` و تأیید `_tn_spin_reviewed=yes` ثبت می‌کند. renderer فقط ۱۲ تا ۱۴۴ attachment تصویری یکتا با `post_parent` همان محصول را می‌پذیرد. تا قبل از این تأیید هیچ دکمهٔ ۳۶۰ نمایشی ساخته نمی‌شود. فایل عمومی یا نشانی خارجی در این فیلد پذیرفته نمی‌شود.

نمایشگر پس از کلیک کاربر اولین فریم را بارگیری می‌کند و با لمس/کشیدن، کلیدهای چپ و راست، Home/End، دکمه و اسلایدر کار می‌کند. برای تأیید، تست `tests/browser/photo-spin.cjs` توالی ساختگی و ایزوله دارد؛ موفقیت آن، وجود فریم واقعی برای محصولات فعلی را ثابت نمی‌کند.
