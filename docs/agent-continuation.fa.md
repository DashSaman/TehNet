## خواسته‌های مالک و تصمیم‌های تثبیت‌شده

- سایت چهار مسیر آموزش، لاب، خدمات و فروشگاه دارد. فروشگاه در `/shop/` و منوی فروشگاه است؛ خانهٔ آموزش/خدمات نباید جایگزین شود. فارسی، RTL و موبایل، هویت تهران نتورک و امکان مدیریت بومی وردپرس حفظ شوند.
- خواستهٔ تجاری، سفارش، انبار و حسابداری یکپارچه است. WooCommerce مرجع سفارش/حساب مشتری و ERPNext مرجع رزرو/انبار/دفتر کل است؛ پیش‌فاکتور قدیمی Core سند دفتر کل نیست. تصمیم و مقایسهٔ راهکارها: [solution-comparison](research/solution-comparison.md) و [architecture](architecture.md).
- قیمت و موجودی منبع، قیمت و موجودی تهران نتورک نیست. کاتالوگ فیزیکی فعلاً استعلامی است. کد داخلی `TN-SN-ID` جای شماره فنی سازنده نیست؛ واحد متر/بسته/قرقره و تبدیل‌ها باید مستند باشند. اختلاف برند، شیلد، جنس روکش، طول یا ادعای تست با حدس رفع نمی‌شود.
- مالک ابتدا حذف واترمارک را منع کرد و سپس مالکیت تصاویر سعید شبکه و درخواست حذف نوشتهٔ فروشنده را صریحاً تأیید کرد. مجوز تازه مبنای پاک‌سازی محدودِ ثبت‌شده شد؛ این مجوز به CAD یا عکس تازهٔ سازنده تعمیم داده نمی‌شود. اصل تصاویر و نشان‌های سازنده حفظ شده‌اند. هیچ ویرایش تازه‌ای در این تحویل انجام نشده است.
- تصویر واقعی و مطابق همان کالا، چرخش و بازشدن اجزای واقعی با توضیح مستند مطلوب است. یک عکس، نمای پنهان یا اندازهٔ میکرونی را اثبات نمی‌کند؛ مدل آموزشی نباید به‌عنوان CAD دقیق کالا عرضه شود. نبود مدل، کاتالوگ استعلامی را متوقف نمی‌کند.
- دربارهٔ پریز قرمز `TN-SN-17989`، عنوان 77214، SKU منبع 77211 و متن 77218 متعارض‌اند. مالک گفت مسئول فروش در دسترس نیست و سایر کارها ادامه یابد. همان سؤال را تکرار نکنید و کد را حدس نزنید.
- استقرار تازه، بازکردن ایندکس و پرداخت واقعی تابع مجوز مربوط و امکان بازیابی‌اند. سفارش، پرداخت، پیام به اشخاص یا پست خارجی آزمایشی واقعی ایجاد نکنید. کارهای مستقل مجاز را با هر مانع متوقف نکنید.
- دسترسی به مدل/ابزار را از نام درخواستی استنباط نکنید. یک مشاورهٔ محدود GLM در مرحلهٔ ۱۵ اکتبر واقعاً ثبت شده؛ این به معنای استفادهٔ مداوم، دسترسی امروز یا اثبات مدل مدیر نیست. در مرحلهٔ ۱۸ اکتبر GLM تازه استفاده نشد. حساب Codex بومی و مسیرهای جداگانهٔ ارائه‌دهندگان حفظ شوند.

## آزمون‌ها: چه چیزی واقعاً اثبات شده است

- **۱۸ اکتبر:** دو API با ۲۵ رکورد، بازبینی ۲۳ تصویر و ۱۷ منبع، خواندن بومی و برابری هش‌های محافظت‌شده؛ ۳۱ قرارداد مدل و ۲۳ قرارداد عکس موفق. [رسید](../qa/exact-media-2026-10-18/verification.json) عمداً وضعیت `evidence-verified-publication-incomplete` دارد. این آزمون، وجود مدل دقیق جدید را اثبات نمی‌کند.
- **۱۶ اکتبر، کلون خصوصی:** ۲۷ بررسی فروشگاه و ۲۰ بررسی کنترل‌های مدل کالای ساختگی موفق. آزمون‌های محلی ۲۳ عکس، ۳۱ مدل، ۴۳ متادیتا و ۱۱ MTU نیز در [رسید](../qa/shop-ux-2026-10-16/verification.json) ثبت‌اند. fixture، مدرک محصول واقعی نیست.
- **۱۶ اکتبر، تولید:** HTTP عمومی محصولات/فروشگاه/خانه و جست‌وجوی فارسی موفق؛ مرورگر فقط ۱۲ بررسی را کامل کرد و در ناوبری SKU فارسی به timeout رسید. وضعیت `verified-with-production-browser-limit` است؛ اجرای کامل ۲۷ بررسی تولید موفق اعلام نشود. برخی زنجیره‌های تست قدیمی پس از timeout اجرا نشدند؛ رسید قدیمی آن‌ها نتیجهٔ تازه نیست.
- **۱۵ اکتبر:** شواهد ERP، sandbox، نقش‌ها، رقابت موجودی، callback تکراری، مبلغ نامعتبر، بازپرداخت متری و بازیابی در [testing](testing.md) و ماتریس پذیرش تفکیک شده‌اند. آن‌ها تأیید بانک تولید، مالیات، حمل واقعی یا افتتاحیهٔ انبار نیستند.
- **۲۵ اکتبر، این تحویل:** فقط تمامیت مستندات، مسیرها، وضعیت رسیدها و diff بررسی می‌شود؛ نتیجه در [رسید تحویل مستندات](../qa/agent-handoff-2026-10-25/verification.json) ثبت می‌شود. آزمون زندهٔ جدید یا استقرار انجام نمی‌شود.

## محیط‌ها و بازیابی امن

نشانی‌های شناخته‌شده: [فروشگاه](https://tehnet.ir/shop/) و [پنل Store](https://tehnet.ir/wp-admin/admin.php?page=tn-store). نشانی‌های localhost در تاریخچه، سرویس دائمی نیستند. دسترسی و ورود باید در جلسهٔ جدید بررسی شود؛ هیچ رمز یا credential در این سند نیست.

در آخرین بررسی بومی، alias اتصال `netauto-main` و کانتینر `tehnet-wordpress` با نگاشت `127.0.0.1:18082` مربوط به همین سایت بود. این‌ها شاهد هویت تاریخی‌اند؛ روی میزبان نامشخص دستور تغییر اجرا نکنید. کلون خصوصی `/root/tehnet-ux-preview-20261016` پایگاه tmpfs موقت داشت. restart آن می‌تواند دادهٔ پیش‌نمایش را از بین ببرد؛ پورت عمومی باز نکنید. کالای ساختگی ۱۸۹ کلون، فقط hidden است و ممکن است در Store API دیده شود؛ هرگز به تولید کپی نشود.

مرجع آخرین runtime، رسید ۱۶ اکتبر با ۲۲ مسیر تطبیق‌داده‌شده و ۹ فایل تغییریافته است. مسیر انتشار `/root/tehnet-releases/shop-experience-20261016-0aeb95218702` و backup خصوصی `/root/tehnet-backups/20261016-190351-store-review` در همان رسید ثبت شده‌اند؛ **خود آرشیوها در Git نیستند** و موجودبودن یا قابل‌بازیابی‌بودن امروز آن‌ها تأیید نشده است. پیش از نوشتن تولید، backup کامل تازه، checksum و راه بازگشت همان تغییر لازم است. فایل env، SQL، کلید، اطلاعات مشتری و نسخهٔ خصوصی به مخزن منتقل نشوند.

این دستورها را از روی تاریخچه کورکورانه تکرار نکنید: deploy کامل Core/theme، `release-site-remediation.py`، importer اولیهٔ عکس روی ارجاع‌های پاک‌سازی‌شده، `release-shop-experience.py --apply` یا rollback قدیمی. هرکدام مبنا و guard تاریخی خود را دارند. SQL را به عقب برنگردانید تا ویرایش‌ها و سفارش‌های تازه از دست بروند. خاموش/حذف‌کردن volume یا DB راه رفع timeout مرورگر نیست.

## قدم‌های بعدی با معیار پذیرش

1. **مدل‌های دقیق:** اول `TN-SN-17929` با نامزد 076561، بعد `17941` با سرنخ RJ11/078731 و `17982` با ادعای 077210. مدارک هویت نمونه، مجوز وب، فایل همان نسخه و اجزای واقعی/مواد/اندازه لازم‌اند. RVT یافت‌شده دانلود و تحلیل باینری نشده؛ BIM ساده‌شده یا مقدار `>0.8µm` حداقل طلای تماس، مدرک لایه‌ها و میکرون کابل نیست. برای همهٔ ۲۵ قلم مانع مستقل در manifest آمده است.
2. **پذیرش مرورگر عمومی:** باقی مسیرهای ناوبری را در اتصال پایدار، فقط خواندنی اجرا و نتیجهٔ جدید ثبت کنید. مسیرهای گذرکرده و timeout را جدا نگه دارید. این کار به بازکردن پرداخت نیاز ندارد.
3. **آمادگی تجاری:** MPN/واحد/تبدیل، قیمت و موجودی افتتاحیهٔ واقعی، شرکت/سال مالی/حساب‌ها، اسناد قانونی، ظرفیت ERP تولید، درگاه معتبر، worker، حمل و اعلان، backup خارج میزبان و هشدارها هنوز باید با شواهد خودشان بسته شوند. روی سرور مشترک کم‌ظرفیت ERP را بدون بررسی ظرفیت اضافه نکنید.
4. **SEO و تجربهٔ خرید:** noindex تا تصمیم انتشار جداگانه حفظ شود. GSC/Ahrefs پیش‌تر محدودیت پلن داشتند؛ داده یا توصیه‌شدن AI ساخته نشود. شمارش facetها، همگام‌سازی علاقه‌مندی حساب و دادهٔ واقعی رفتار/تبدیل در backlog هستند. کل پروژه به‌خاطر تکمیل ظاهر یا گذشت تست ساختگی «تمام» نیست.

## شروع امن و ثبت نتیجه

از ریشهٔ مخزن، فرمان‌های زیر فقط وضعیت و قراردادهای محلی عکس/مدل را می‌خوانند. نیاز به PHP CLI دارید؛ مسیر runtime محلی قبلی `../php-runtime/php.exe` بوده و در Git نیست.

```powershell
rtk git status --short
rtk proxy git branch --show-current
rtk proxy git log -5 --oneline
rtk proxy git diff --check
rtk proxy powershell.exe -NoProfile -Command "Get-Content -Encoding utf8 HANDOFF.md -TotalCount 32"
rtk proxy python -X utf8 qa/agent-handoff-2026-10-25/verify-docs.py
rtk proxy php tests/product-evidence-unit.php
rtk proxy php tests/product-photos-unit.php
```

ابزار بومی `ops/collect-exact-media-evidence.py` فقط خواندن وردپرس است، اما SSH/شبکه و حساب مجاز می‌خواهد و بر وضعیت فعلی ۲۵ قلم guard دارد. خروجی را در مسیر با تاریخ جدید بدهید. verifierهای قدیمی بعضاً رسید ثابت تاریخ‌دار را بازنویسی می‌کنند؛ قبل از بازاجرا کد و مقصد خروجی را بخوانید و شاهد تاریخی را حفظ کنید. اجرای تاریخی موفق مجوز اجرای مجدد migration یا bootstrap نیست.

برای جست‌وجو RTK و محدودهٔ مرتبط، برای PowerShell مسیر `rtk proxy powershell.exe -NoProfile -Command ...` و برای Python متن UTF-8 و `-X utf8` به کار ببرید. خروجی failure را کامل ببینید؛ در شکست فیلتر، recovery log یا `rtk proxy` را بخوانید. از خلاصهٔ ناقص، علت خطا یا نتیجهٔ آزمون را حدس نزنید.

پس از کار معنادار، HANDOFF/PROGRESS/TASKS و سند موضوع را به‌روز کنید. رسید جدید باید تاریخ، محیط، دستور، exit code، شمار دقیق بررسی‌ها، محدودیت‌ها و هر شکست حل‌نشده را داشته باشد. وضعیت‌های «آماده»، «آزمودهٔ محلی»، «منتشرشده» و «تأیید زنده» را جدا نگه دارید؛ سپس diff کامل مرتبط و آزمون مناسب را مرور، commit و وضعیت push را دقیق گزارش کنید. تیم‌های بعدی نباید برای کشف نتیجهٔ قبلی مجبور به بازخوانی گفتگو شوند.
