# ادامهٔ تصویربرداری بدون تصرف دسکتاپ مالک

دستور مالک۵نوامبر: هیچ کلیک، تایپ، جابه‌جایی/فعال‌سازی پنجره یا تغییر تنظیمات برق/قفل/نمایشگر در Windows میزبان. WinBox میزبانِ همین کار بسته شده است. ادامهٔ کدنویسی/SSH/مرورگر باید headless باشد؛ UI فنی در نمایشگر جداگانهٔ مهمان انجام شود. این قاعده با سکوت یا گذشت زمان برداشته نمی‌شود.

## مسیر اجرا و اعتبار عکس

۱. از محیط موجود و موجودی خصوصی استفاده کنید؛ VM یا پروژهٔ تکراری نسازید. QEMU قابل‌حمل/TCG، دیسک overlay جدا، مدیریت hostfwd فقط loopback با restrict=on و لینک داخلی؛ هیچ TAP/adapter/driver میزبان یا LAN مشترک تغییر نکند.

۲. ابزار Linux WinBox رسمی در مهمان GNS3 اجرا شده است. Xvfb با نمایشگر1536×960 و nolisten tcp، بدون نمایش در دسکتاپ میزبان کار می‌کند. HOME/XDG مستقل مهمان با profile میزبان اشتباه نشود؛ تلاش اولیهٔ جداسازی profile WinBox Windows مؤثر نبود و آن برنامه بسته شده است.

۳. برای هر عمل، پنجرهٔ واقعی مهمان و مقصد تازهٔ لاب را بررسی کنید، سپس همان‌جا یک عمل انجام دهید و framebuffer را ثبت کنید. xdotool فقط داخل مهمان/نمایشگر اختصاصی مجاز است. از PID/title/نسخهٔ واقعی استفاده شود؛ delay ثابت یا started بودن node جای پذیرش UI/سرویس نیست.

۴. XWD/PPM اصلی خصوصی و PNG تبدیل فرمت، زمان، ابعاد، SHA256 و مختصات گزینه نگهداری شوند. متن/نتیجهٔ رابط یا رمز به عکس اضافه نشود. کادر توضیح CSS است؛ اصل بدون کادر با full-size link حفظ شود. عکس فرایند ورود/رمز/Backup خام منتشر نشود.

۵. Web UI در مرورگر headless و با route محدودِ خواندنی بررسی شود. قبل از تصویر منتظر selector/متن واقعی و paint بمانید؛ screenshot سفید یا API started شاهد نمایش صحیح نیست. نام خودکار node و نسخه UI را از مشاهده بخوانید، نه از ورودی create.

## وضعیت موجود و ادامه

سه CHR مستقل7.25.1 و WinBox4.5 مبنای۳۹تصویر و پذیرش DHCP/Undo/Restore/Snooping هستند. دو مقالهٔ موجود، native60/renderer16/browser1590 و exact restore را گذرانده‌اند؛ PR88 پس از تأیید صریح مالک ادغام و همین دو مقاله با backup/drift/rollback منتشر و مستقلاً پذیرفته شدند؛ این مجوز به بسته‌های دیگر تعمیم داده نمی‌شود. دادهٔ مشتری/25قلم/noindex/payment/MyTel و گیت‌های امنیتی حفظ شوند.

GNS3 Server2.2.61 / Web UI2.2.58 در مهمان جدا اجرا شده؛ پروژهٔ دو node/یک لینک ساخته و تصاویر واقعی گرفته شده‌اند. CHR داخلی هنوز در Load system است؛ console/ping پذیرفته نشده و nodeها برای کاهش مصرف CPU متوقف‌اند. RAM1024/readback و inner TCG تأیید شده‌اند؛ علت boot تعیین نشده. پروژه، image معتبر، overlayها، snapshot پیکربندی و لاگ‌ها در موجودی خصوصی حفظ‌اند. مسیر نسبی API image باید در برابر images_path واقعی تفسیر شود. bootstrap قبلی در مرحله initial متوقف شد و رمز تولیدشده اعمال نشده؛ آن را رمز فعال یا چرخش رمز تاریخی ننامید.

محصورسازی اولیهٔ پوشهٔ خصوصی باعث خطای ACE شد. دو تعمیر گسترده در بازبینی خودکار رد شدند؛ تعمیر فعلی فقط۶فایل با اجازه صریح مالک بود. دیگر فایل‌های قدیمی هنوز ممکن است محدود باشند. مجوز گسترده، تغییر ارث‌بری یا دسترسی عمومی برای دورزدن خطا ندهید. مقادیر و مسیرهای دقیق فقط در handoff خصوصی؛ پیش از هر commit/push، publication_guard و اسکن مقادیر شناسایی‌شده لازم‌اند.

برای درس GNS3 ابتدا boot/console و بستهٔ واقعی در همان پروژه را بپذیرید؛ بعد آموزش تصویری و سناریوی ضبط را کامل کنید. عکس سبز node، شمارش تست، اسکریپت ضبط یا لینک منبع، پذیرش packet/ویدیو/رتبه/رقابت نیست. مدت واقعی ضبط/approval تا اجرای واقعی null می‌مانند.
