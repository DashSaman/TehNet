# واردسازی و بازگشت کاتالوگ

منبع عمومی در ۱۵ اکتبر ۲۰۲۶ دوباره خوانده شد: ۲۵ محصول با شناسه یکتا، صفحه دوم خالی و ۱۲ دسته رسمی با parent واقعی. گزارش جداگانه `saieedshabake_product_count_2026-10-15.txt` در دسترس نبود و استفاده نشد. فایل `content/catalog/saieedshabake-2026-10-15.json` حاوی داده نرمال‌شده و وضعیت بررسی تک‌تک اقلام است.

هر کالا SKU مستقل `TN-SN-ID` و source_key مستقل دارد. داده قیمت، stock و URL تصویر منبع فقط در `source_observation` برای بازبینی است؛ importer آن‌ها را به قیمت/موجودی/رسانه Woo منتقل نمی‌کند. توضیحات اختصاصی و نظرات منبع منتقل نشده‌اند. هیچ واترمارکی دستکاری نشده و هیچ مدل سه‌بعدی واقعی ادعا نشده است.

همه اقلام ابتدا draft، بدون قیمت، stock صفر و backorders=no هستند. ویژگی‌های استخراج‌شده در meta خصوصی «داده منبع تأییدنشده» ذخیره می‌شوند؛ `verified_specifications` خالی است تا شماره فنی و سند مدل دقیق تأیید شود. دسته‌های رسمی منبع مستقل از گروه‌بندی تحلیلی چهارگانه حفظ شده‌اند.

نمونه مسائل کشف‌شده: محصول 17989 در عنوان 77214 و SKU منبع PWR-WHT-77211 دارد؛ 17941 و 17935 ترکیب تلفن/Cat6 دارند؛ SKU برخی کابل‌های Nexans نام Legrand دارد؛ ادعای Permanent/Channel بدون گزارش مدل/بچ تأیید نشده است. عنوان فروش از ادعای تست تأییدنشده پاک می‌شود؛ اصل عنوان در source_title برای حسابرسی می‌ماند. اصلاح فنی به‌صورت حدسی انجام نمی‌شود.

دیتاشیت‌های عمومی Legrand برای [RJ45 Cat6](https://assets.legrand.com/pim/NP-FT-GT/F01418EN-04.pdf) و [RJ45/RJ11/RJ12](https://assets.legrand.com/pim/NP-FT-GT/F01679EN-00.pdf) نشان می‌دهند نوع کانکتور و مدل دقیق باید تفکیک شود؛ این اسناد به‌تنهایی تطابق مدل نامشخص منبع را ثابت نمی‌کنند.

## فرمان‌ها

نرمال‌سازی فایل‌های عمومی دریافت‌شده:

```text
python -X utf8 ops/catalog/catalog.py products.json categories.json content/catalog/saieedshabake-2026-10-15.json
```

با TehNet Store و WooCommerce فعال، `wp tehnet catalog import /path/manifest.json` فقط dry-run است. افزودن `--apply` واردسازی واقعی در محیط local/staging/development را انجام می‌دهد. Production عمداً مسدود است؛ هیچ تغییر خاموش environment برای دورزدن gate مجاز نیست.

واردسازی creation-only است: SKU و نگاشت منبع تعارض را رد می‌کنند؛ اجرای مجدد همان manifest محصول را تکثیر یا ویرایش انسانی را بازنویسی نمی‌کند. تغییر manifest نسبت به نسخه موجود نیاز بررسی دارد. قفل یکتای DB و transaction از اجرای هم‌زمان ناسازگار جلوگیری می‌کنند. قفل مانده پس از قطع فرایند باید پس از بررسی run و DB دستی بررسی شود؛ خودکار حذف نمی‌شود.

Run ID خروجی را حفظ کنید. `wp tehnet catalog rollback RUN-ID` ابتدا تمام fingerprintها و draft بودن کالاها را بررسی و فقط کالاهای همان run را soft-trash می‌کند؛ ویرایش انسانی، انتشار یا تغییر مالی مانع rollback می‌شود. قاعده soft-trash باید فعال باشد. دسته‌ها برای حفظ ساختار و رابطه با سایر اقلام حذف نمی‌شوند؛ این بازگشتِ کالاهاست، نه حذف ساختار دسته‌بندی.

آزمون واحد normalizer RED→GREEN انجام شد؛ آزمون WordPress واقعی در `tests/catalog-integration.php` آماده است و نتیجه اجرای آن باید جداگانه ثبت شود. وجود اسکریپت معادل موفقیت آن نیست.
